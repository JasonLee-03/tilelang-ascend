## §0 适用判定

按 SKILL.md Step 2 判定算子类型后：

| 特征 | 适用章节 |
|------|----------|
| **CV 融合混合型**（生成码同时含 `IS_ASCEND_AIC` + `IS_ASCEND_AIV` 段） | §1-§5、§7、§8 全部适用；§4 各定律适用于任何 AIC/AIV 耦合闭环算子，不限 attention |
| **attention 家族**（MHA / GQA / MLA / FlashAttention / varlen / MTP 形态） | 额外适用 §6 收益排序，以及 flash_attn_optimize.md 的全部技术点 |
| 纯 Vector / 纯 Cube 算子 | §1 测量纪律与 §2 归因方法学仍适用；§3/§4 多数定律以「耦合闭环」为前提，引用前核对每条的适用条件 |

**为什么单独立手册**：attention 是典型 CV 耦合算子——Cube 算 QK^T 与 PV、Vector 做 softmax/掩码，两侧经 workspace 或 L0C 通道形成生产者-消费者闭环。闭环结构下，「让某一侧更快」的直觉优化会被对侧等待吸收（§4.1 吸收律），瓶颈判定、候选分类、读数解释都与单管算子有系统性差异。MHA 在 Developer 模式下先做常规调优（会话 1-2，0.13x→0.55x），触及结构边界后 Expert 化重构（会话 3-6，→0.9054x），再做结构级专项（会话 7-13，→0.97x）——三条轨道的经验教训全部沉淀在此。

## §1 测量纪律（Step 1 与全程读数）

### 1.1 计时唯一依据

- **wall 唯一依据 = msprof timeline `op_summary` Task Duration 中位数**（warmup 5 + iters 20 起步；关键判决加密度到 n=25）。禁止 Python/Torch 计时（含 `time.perf_counter` 包 launch 的口径）。
- 有权威评测框架（cann-bench 等）时以其为准权威，本地 msprof 与其互验；**两口径可差 57%**（case10 有效带宽 bench 口径 625 vs 本地 981 GB/s，会话 iter24-26 分析轮），报告数字必须双列并注明口径。
- 环境：`source set_env.sh && export LD_LIBRARY_PATH=/usr/local/sqlite3/lib:$LD_LIBRARY_PATH`——缺 sqlite3 时 msprof CSV 导出**静默失败**（会话 1 踩坑）。

### 1.2 噪声带与采纳规则（全程不可破）

- 噪声带 **3%**；采纳规则：**>3% 提升采纳 / 无变化回滚 / 性能下降回滚 / 精度失败必回滚 / 运行失败回滚**。
- 中止条款：**连续 3 次无 >3% 提升** → 收口（MHA 会话 3/4/11 均由此条款正常收口，收口不是失败）。
- **小 kernel（wall < ~50us）环境漂移**：同一字节级文件三段测量 case10 单调漂移 33.87→34.90→35.43us（+4.6%，超噪声带），大 kernel 无漂移（会话 9）。守卫判定必须附**同文件多段测量漂移基线**（≥2 次同态复测取漂移包络）；超带读数先做 IR 逐字节排除 + 漂移归因再判回退；禁止用单次读数对硬约束线做采纳/回滚裁决。

### 1.3 msprof pipe ratio 语义陷阱（高频误判源）

`aic_*_ratio` / `aiv_*_ratio` 是 **busy 比（含 stall 归属）**，不是真实发射比，两者可差一个数量级：

- 实证（iter24）：case9 `scalar busy 97.54%`，而真实发射（single 20.25 + dual 56.29 = 76.55us）仅 **9.12% wall**——busy 的 ≈91% 是 stall（`mte1_stall` + `wait_idN`）。MHA 曾长期把「C scalar 95.5%」当作发射饱和证据，据此设立的「生死门」实测根本不成立。
- 判定 pacing 管必须用 **发射当量 `single_time + 2×dual_time`** 或该 pipe 的绝对 busy 时长，并与 `*_stall`/`wait_idN` 分列。
- `*_stall` 各桶之间**可能重叠**（同一等待同记入 `wait_id2` 与 `mte1_stall`，加和残差 100.7%/108.0% 属正常）；只有 single/dual vs busy 这对计数器互斥，可作判决依据。
- **任何以「某 pipe busy% 高」为由的立项/否决，必须先给出该 pipe 的发射/stall 拆分。**误读的两个方向都致命：把 stall 阴影误判为吞吐饱和（错误否决候选）、把最大 busy 管误判为 pacing 管（错误立项）。

### 1.4 wait_idN 读数纪律

- `wait_idN` 之和**系统性高估可回收 wall**：延迟侧高估 6.8~9.4×（消融实测转化率 10.69%/14.69%），工作消除侧高估 64.8~844×（转化率 1.54%/0.12%）（iter25/26 消融上界探针定量）。
- 等待被消除后**不消失而是迁移**（case9 `aiv_wait_id3` 0.33→308.63us；case7 `aic_wait_id1` 10.59→213.81us）。报告消融/优化收益时必须同时给出**转化率**与**迁移目标计数器**。
- 激活信号可用 **`wait_idN` 列存亡本身**（msprof 删全零列；生产态列集合与跨核 SEM 方向分割 1:1 对应，`wait_idN` ↔ `CrossCoreWaitFlag(N)`）。
- stall/wait 类读数**只指示位置、不指示收益**（§4.11 伴生症状定律）。

### 1.5 camodel（指令级仿真）两禁

camodel / msopprof simulator 是二级归因利器（§2.1），但有两禁，各有实判：

1. **禁作收益定量**：#R6-2 camodel C wall -19.0% / FIXP -24.4%、机制指标全按预期改善，真机 msprof 4/4 case 噪声带内且方向不一致（case6 +0.57%）→ 回滚。模型偏差实证：camodel FIXP sum 29.8us **超过真机全 kernel wall 24.65us**（会话 6）。
2. **禁作 pacing 管归因**：case9 C FIXP camodel 94.95% vs 真机 32.8%；case6 92.4% vs 28.8%（真机最忙管实为 mte2 54.1%）。若信 camodel 会把瓶颈锁错到 FIXP 墙（会话 7）。

**允许用途 = 机制是否激活的定性判定**（段结构变化、气泡消除、重叠占比方向、token 流）。camodel 与真机方向背离时按真机裁决，并把背离本身归档（提示该 pipe 争用建模失真）。采纳判据永远以真机 msprof wall（同会话对比 + IR 未变守卫带幅）为准。

### 1.6 带宽参照系三规则

1. 任何 GB/s 常数/读数必须标注**供数介质**（HBM 唯一字节 / L2 命中 / 混合）与**测量形态**（行粒度、跨步、核数、busy/发射口径），禁止跨介质直接对比。
2. 利用率计算**分子分母同介质**（HBM 唯一字节 ÷ HBM 峰值；L2 流量 ÷ L2 聚合带宽）。
3. busy 期速率高于同介质上限时，先按字节占比剥离 L2 命中成分再下结论（标注剥离为估算/实测）。

反例框：归档常数「MTE2 持续 125.2 GB/s/核」实为 L2 命中域的 busy 速率，被误用为 HBM 域引擎参照系，得出「decode 单核仅 48-51 GB/s，引擎缺口巨大」的错误图景**延续 5 个会话**；实测单核连续 stream 249.6 GB/s 证明引擎能力远快于此，48.3 GB/s 恰是布局上限（§4.12）的独立复现（iter24-26 分析轮）。

### 1.7 L2 计数器粒度效应

msprof L2Cache 计数单元（本环境 128B）可小于访存突发粒度（256B 行），此时每次行读被记「1 miss + 1 hit」对，**名义命中率钉在 ~50% 而物理零复用**。核对方法：

- 与逐访问事件模型对账（case11：miss 合计 53,277 ≈ 52 槽×1024 行，±0.05% 吻合 ⇒ 判定计数伪影）；
- 「有 L2 复用」结论必须同时通过有效带宽（唯一字节÷wall）交叉验证；
- 快速签名：同 kernel 不同行宽形态的命中率跳变（256B 行族 ~52.5% vs 512B 行族 3.0%）。

### 1.8 T.copy 微基准的生成码核验

凡用 `T.copy` 做**定量微基准或新访存形态**，必须先 `get_kernel_source()` 核验生成的 copy 模板参数（形状/stride）并做搬运量对账（字节数 = 预期/iter）再采信计时。实证：3D 源 tile → 异形状目的的「8KB 整行合并装载」静默退化为单行形态 `copy_gm_to_l1<half,32,128>`，无报错，读数（17.7us）失去物理意义；对照组 2D 形态经生成码核验（`stride 4096` 逐字复现生产访存）后读数可信（iter24-26 分析轮）。

## §2 归因方法学（Step 2/3 瓶颈诊断）

### 2.1 分辨率分级

| 级别 | 工具 | 回答的问题 | 何时升级 |
|------|------|-----------|----------|
| 一级 | msprof op 模式（PipeUtilization/OpBasicInfo）+ timeline | 算子级 wall、pipe busy/发射拆分、wait 结构 | 默认起点，成本低 |
| 二级 | camodel 指令级仿真（`msopprof simulator --soc-version=...`） | 指令/pipe 级时序：重叠占比、段结构、气泡、token 流 | 一级收敛到「固定结构成本/协议开销/等待占比高」但无法细分；或多核协作 + 怀疑 latency/sync-bound |
| 微基准 | 算子外独立 tilelang kernel（纯 `T.copy`/纯 mma 形态矩阵） | 硬件形态常数（布局带宽上限、引擎能力、harness 自校验） | 需要区分「物理墙 vs 实现缺口」时 |

camodel 战果示例：msprof-only 分析遗留数个会话的「case7 每迭代固定结构成本」定性结论，camodel 一次定位到「MTE↔VECTOR 重叠仅 5.30%、VECTOR 被切成 11 段（6 段是 8.6~54.1ns 微型碎片）、C 核 FLOWCTRL 占 wall 83.2%」的具体机制，据此设计出单块任务批处理（#R5-1），重叠提升到 20.93%（×3.95），case6 加速比 0.584→1.083x（会话 5）。

**camodel 解读陷阱（cycles 重叠记账）**：`*_instr_exe.csv` 的 `cycles` 列是重叠阻塞记账，不是墙钟可加时间——单核 Σcycles 可超实际 wall 6.6×（120,328 cycles ≈65us vs wall 9.83us）；WAIT/BAR 类指令的大 cycles 对应「发射→队列排空」等待窗口，与其它 pipe 真实工作大量重叠（曾据 `BAR=62.25% cycles` 误判「协议税主导 wall」，实际 BAR 在时间轴上只是 dur≈0.5ns 的发射标记）。**真实 wall 归因必须基于 merged `trace.json` 做 pipe 级 busy-union + gap-covering 时间轴分析**（按 pid×pipe 分组求 union busy、扫描线算重叠占比、按 gap 阈值切段检测碎片化），不能汇总 instr_exe.csv 的 cycles 列。

### 2.2 双向 A/B 排除法（判定 pacing 管的完备形态）

耦合结构下「哪根管是墙」不能只看 busy 占比，用双向实验判定：

1. **加速侧**：对候选管做单侧加速探针，观察对侧等待响应。1:1 吸收（wall 零响应）⇒ 该管非杠杆，或结构为交接链 bound（歧义态）。
2. **减速侧**：加速侧被吸收时，引入已知增量使该管**被动变慢**，验证 wall 是否同向上升。wall 随该管减速而升 ⇒ 该管确为 pacing（收益只能来自其真实工作削减或结构删除）。

MHA 三点校准：r7-1 加速 V 侧（vector_stall -37%）→ C `mte1_stall` +33us 吸收，wall +0.31%；r7-2 加速 C-G1（`mte1_stall` 412→188us，-54% 靶心命中）→ C `wait_id2` 324→545us 吸收，wall +0.35%；r9-1 减速侧（V.vec 被动 +21.8%）→ wall +12.4%，传导系数 ≈0.57 且方向确定 ⇒ V-paced 因果**双向确证**（会话 7/9）。减速侧实验必须精度门禁全过后按性能规则回滚——回滚的实验也是合格归因产出。

### 2.3 内存带宽墙四步归因法

「实测有效带宽 < HBM 峰值」**不得直接判为可回收空间**。凡诊断结论为「带宽利用率 <70% 峰值 ⇒ 存在空间」时必须先走完四步：

1. **介质核算**：用 L2Cache/Memory CSV 分离 HBM 唯一字节与 L2 往返流量（§1.7 粒度效应先排除），利用率分子分母同介质配对。
2. **算子外布局形态微基准**：把生产访存形态做成矩阵（行粒度 × 跨步 × 连续对照 × L2 驻留 × 核数档位），生成码核验形态同一性（§1.8），**连续对照必须打到峰值 ≥95% 以自校验 harness**（MHA：连续 1469 GB/s = HBM 读峰 1472 的 99.8%）。
3. **baseline/业界实现 op 模式对照**：同 shape 采集对方实现，判定差距是「对方更优机制」还是「双方同墙」——这是 EV 的存在性证明（MHA：CANN baseline case11 cube 路径 MTE2 duty 94.6% 近饱和仍仅 894 GB/s = 同墙；case15 vector 路径 1448 GB/s = D=256 空间存在性证明 + 达成机制情报）。
4. **每槽/每迭代 wall 分解**：上限项 vs duty 项分摊（case11 每槽 5.80us 中 94% = 布局上限算术必然；case15 5.25us 中 31% = duty 缺口）。

判词规范：**物理墙 ⇒ 「无空间（墙确认）」；duty 墙 ⇒ 「条件空间 + 上界倍数 + 捕获路线与硬限相容性核对」**。MHA 借此把 decode 域「622-999 GB/s vs 峰值 1472」的长期开放缺口拆成 D=128 物理墙（6 case 不可达，任何实现含 CANN 自家都只能逼近 966 GB/s 聚合上限）与 D=256 duty 墙（1.45× 条件空间）两类（iter24-26 分析轮）。

### 2.4 挂死类缺陷：毒化矩阵法

**症状**：aicore timeout 无报错挂死（如 507014 / 240s SIGKILL exit 137），无 traceback，stdout 因块缓冲被丢弃，**静态令牌收支审计全平衡仍挂**。此类缺陷禁用 `T.printf`/`T.dump_tensor` 渐进定位（dump 本身改变时序/无法输出），改走六步：

1. **bisect 粗定位**：生产体删半/删 chunk 缩小范围（生产体 bisect 优于 mini 隔离核——后者踩 jit 工厂框架陷阱，见 §5.7）。
2. **单因子删除变体矩阵**：分别删可疑指令类/载荷/换布局/延迟释放，逐个隔离「哪个指令类 × 哪个边际条件」是毒化因子（MHA E 系 9 变体：E15 排除 FIX、E16 定罪载荷重载、E17 定罪 mma 二次读取）。
3. **生成码复核**：hang_*.cc 与正常变体逐参数同形比对，排除 codegen 伪影（确认是纯硬件行为）。
4. **归纳统一判读**：把各变体结果归纳成机制定理（如 §4.4 L0B 双重毒化）。
5. **终局实验 + 判据预登记**：定义「唯一安全谱系推广」实验，**运行前落档判据**（MHA：「T1 HANG ⇒ 全部可表达形态穷尽 ⇒ [DESIGN_ERROR]，≥3 方案实测达成」）——判决成为机械执行而非临场博弈，杜绝「再试一个变体」的沉没成本漂移（挂死调试是最易漂移的缺陷类，每个变体都「差一点」）。
6. **静态不可能性证明族收口**：穷尽条款 + 全部变体/矩阵日志/生成码留存（防重复探索资产）。

MHA 会话 10 用 15 变体 ~7h 完成从「全形状挂死」到「硬件定理（bN 上界定理）+ 穷尽证明」的闭环。

### 2.5 竞态类缺陷：最小复现保真度阶梯

非确定性数据损坏（同一输入两次运行损坏范围不一致，如坏 slice 3/64 vs 24/64）优先怀疑竞态/令牌失配。算子外最小复现必须先过**保真度门**：

1. 第一步是把**已知失败配置**在最小结构上跑出原缺陷；
2. 跑不出 → 逐级补齐上下文（跨核交互 → 并发 scope → 真实寻址/批轮），期间**不得下「假设证伪」结论**——「最小复现全 CLEAN」只能证明该结构不含缺陷，无判别力（MHA #R6-3 两级 240 launch 全 CLEAN，因缺失跨核 SEM 悬停窗口等上下文而对变体无判别力，只能归档「根因未定案」）；
3. 保真度门通过后，CLEAN 才可用于收窄假设或验证安全变体；
4. 预算内过不去保真度门 → 改用**以完整 kernel 为基座的消融法**（逐项移除可疑因子）。

kernel 内判决性实验的「恒真条件替换法」：把守卫条件换成运行期恒真（代码形状/flag 位置完全不变、实际不跳过任何操作）→ BITEXACT 则证明机制本身无罪，问题特定于谓词语义 + 令牌平衡（MHA #R5-3 用此法证明 runtime-if 包 `T.copy` 机制无罪、罪在「跳过真实 DMA 但配对 flag 未同步条件化」）。

### 2.6 瓶颈迁移追踪

靶心命中 ≠ 收益兑现。消灭一个 stall 后新瓶颈常在别处显现，必须复采归因而非直接下结论：case9 S1 mma 化后 `aic_scalar_mte1_stall` 739.4→412.2us（-44%，靶心命中），但 `aic_wait_id2` +114%——新墙 = C↔V 四相位耦合链延迟 + D256 流量强度，而非单管吞吐（会话 7）。同理 r13 采纳后 `scalar_t` 336→411us = 99.7% wall，墙从「duty 墙」迁移为「scalar 固定段地板」，下一杠杆方向随之改变（会话 13）。**每次采纳后强制重判 pacing 管身份**，写入下一轮候选排序依据。

## §3 立项前判据（EV 预登记制，Step 3）

核心思想：把「实现完再测 ±0.3%」升级为「**实现前用探针/静态审计钉死 EV 上界**」。MHA 谱系累计 5+ 次单侧类候选走完整实现-门禁-复测-回滚全链路才被判死（r7-1 / r7-2 / r8-1 / r9-1 / #R3-2 / #R4-2b / #R6-2），每次都付了完整门禁成本，结论均为 wall ±0.3% 或劣化；而 GATE 0 探针三轮总成本 ≈2 小时，全部在实现前完成判决。

### 3.1 手段杠杆性质前置分类（Part A 清单的第一道过滤）

对 CV 耦合闭环算子，每个候选先分类，分类决定判决路径：

| 类别 | 定义 | 例子 | 判决路径 |
|------|------|------|----------|
| **交接结构删除类** | 删除批轮次/排空点/任务边界-批界耦合/协议段 | flat (task,kv) 槽流、任务批处理、O 直写、barrier 移除 | **最优先立项**——不被吸收（§4.1），EV 用 §4.9 模型预估 |
| **单侧吞吐类**（速度/字节/指令削减/宽化） | 只让某一侧更快/更少字节/更少指令 | w1 dtype 瘦身、L1 双槽、L0B 槽旋转、V 宽通道、指令融合 | **先过 GATE 0 消融上界门（§3.2）**；wall 双侧各有 ≥200us 级等待余量、或已有一次 1:1 吸收实证时，直接跳过不立项（登记证据性关闭 + 复活前置条件） |
| **结构/框架类** | 改变同步语义、调用边界、模板实现 | gemm_v0 opt-in per-buffer 同步、形态分派重构 | 走 §7.4 预登记判据 + §8 框架级门禁 |

分类依据 = §2.2 双向 A/B 已测得的 pacing 结构。未做归因就分类 = 盲猜。

**「大等待余量」双口径判定**：绝对量口径适合大 kernel（wall ≥ ~200us）——双侧暴露等待（`wait_idN` + `*_stall` 中的暴露成分，按 §1.3 拆分）各 ≥200us 级；占比口径适合小 kernel——双侧暴露等待各占 wall ≥20-30%。任一口径满足即视为「双侧大等待余量」，单侧吞吐类直接跳过。两口径都贴边时按占比口径判（小 kernel 的绝对量天然小，不构成豁免理由）。

### 3.2 GATE 0：消融上界门（单侧类候选强制前置）

凡候选被诊断为**单侧速度类/字节类/事件类**，必须先构造 timing-only 消融探针测其上界：**上界 < 采纳门（默认 3%）⇒ 直接证据性关闭，不进入实现**。方法 = 把候选想攻击的成本项**完全消除**（比任何加速类干预更强的证据：完美优化也不可能优于「彻底删除」），测 wall 响应即得 EV 天花板。

探针四项工程要求：

1. 数值故意错误 ⇒ 禁精度对比、禁入 baseline、禁提交；
2. 原位 `if False:` 改写保持行数恒定 ⇒ diff 行数可精确断言；
3. token 收支与生产态同构或逐一相等（防 HANG）——**首选范式 = 只删 DMA 载荷、保留全部 flag 轮**（收支逐一相等 27/32/137/137、IR 级 `SetFlag` 62→62、`CrossCoreSetFlag` 9→9，且使 §3.3 的 X 病理结构性不可能）；
4. 必须报 rel_max 确认消融激活（排除假阴性）。

**按候选类型的探针构造**：

- **字节/指令削减类**：原位删除目标载荷/削减段（`if False:`），token 收支同构——wall 响应即「完全消除」的上界；
- **藏延迟类**（预取/双缓冲，攻击对象是「装载暴露等待」）：探针形态 = 原位删除该装载、保留全部 flag 轮，使暴露窗口归零——实测 wall 差 = 该装载在关键路径上的暴露成本总额 = 预取类候选上界（**完美预取也不可能优于完全消除**）。iter24 判例：q_l1 双缓冲候选 → Q prologue 消融（fbm 2 行 / Form A 3 行 delta），实测可回收暴露成本 **≤0**（case9 +0.288% p=0.177 / case7 +0.871% p=0.025 显著劣化）⇒ 该装载已被 ≈100% 重叠，上界 [-1.48%,+0.33%] 比 3% 门低 ≥9×，NO-GO；
- **交接类**（跨核 SEM/协议段削减）：必须走 §3.3 六条规则（成对删除、flagId 钳位、消融级次非单调安全）；
- **工作消除类**（架构级重构删除整段 DMA/计算）：零污染判据不适用，走 §3.4 三段式污染账。

三轮命中实录（iter24-26，判决全文 `examples/mha/perf_tuning/gate0_verdict_iter24.md` / `gate0b_verdict_iter25.md` / `gate0c_verdict_iter26.md`）：iter24 杀死 q_l1 双缓冲候选（上界 [-1.48%, +0.33%]，比 3% 门低 ≥9×，且 case7 +0.871% p=0.025 显著劣化）；iter25 给交接延迟族定总闸门（case9 −9.358% / case7 −13.426%）；iter26 静态审计（零编译零运行）杀死缺口①（L0B 128KB = 硬限 2.00×）与工作消除侧（上界仅 1.0060×/1.0004×）。

### 3.3 交接类探针六条强制规则（跨核 SEM 消融）

1. **跨核 SEM 消融必须成对删 wait+set**。只删 wait 保 set 在 Ascend 上是无效探针且**比生产态更慢**：`CrossCoreSetFlag<mode,PIPE>` 是阻塞至 PIPE 排空的标量指令，删 wait 后每次 set 变成生产态从未有过的全管排空阻塞点（实测 paired 差 +102.8~+218.8us p≤1e-4，最差变体 wall +15.823%；计数器指认：发射当量不变而 scalar_time 涨到 =aic_time 的 100%、cube_stall +38055%）。成对删除使计数器冻结在 init 值，全域无 `CrossCoreWaitFlag` 残留 ⇒ 跨核 HANG 结构性不可能。
2. **flagId 钳位约束**：CANN 硬约束「同一 flagId 的计数器最多设置 15 次（未消费）」。细粒度协议（如 `CROSS_INTERVAL=1`）每核每 flagId set 可达数百次，合法性**完全依赖 set/wait 每槽 1:1 交错**。钳位在「该 flagId 无残留 waiter」时无害、在「落后侧仍 wait 它」时致命 ⇒ **消融级次非单调安全**——字面「删一侧全部 wait」看似更彻底，实际非法并 HANG；须逐级做 outstanding 深度构造性证明。
3. `wait_idN` 列存亡本身即激活信号（§1.4）。
4. 必须用发射当量（single+2×dual）排除「指令变少」混淆（强制检查项）。
5. 报告吸收律转化率 + 等待迁移目标计数器（§1.4 定量）。
6. **闭环互等结构中单侧消融的因果解释不成立**：只删 V 侧等待，C 侧等待却免费坍塌（`wait_id2` 211.86→0.59us）——一侧的等待就是另一侧的延迟，互相生成、不可独立消融。结论只能表述为「合计上界」，不得拆算为单侧收益。

### 3.4 工作消除类探针：三段式污染账（WE 规则）

工作消除类探针（架构级重构会整体删除某些 DMA/计算）**不适用**交接类的「真实工作管零变化（零污染）」判据——被消融的正是真实工作项。替代判据：

1. **被消融项**计数器须如预期归零/下降（`aic_fixpipe_time` 336.71→0.00、`L0C_to_GM_datas` −100%、消除 37.8/54.0 MB）；
2. **未被消融项**须零变化——黄金标准 = 某关键真实工作管在多臂间**逐位相同**（`aiv_vec_time` 468.58/468.58/468.58 三臂一致）；
3. **发射当量**变化须可解释（132.84→121.85）。

辅助激活证据：IR 指令清单差分（`copy_l0c_to_gm` 3→0 等逐 family Δ 计数）+ 逐调用溯源（生产态 4 条 vs 变体 3 条，被删的恰是目标那条）。

**WE-6 反向失效模式**（本类探针最大陷阱）：被消除的**写**可能正在为相邻的**读**提供缓存局部性——只删写使读侧 miss ×1770、达成带宽 −11.01% ⇒ **写侧不可单独移除**，且此时上界为负、不可解释为「该工作无价值」。必须同时采集 L2 命中率与 miss 绝对数。

**多分量上界不可相加**：消除工作后增量恰落在与延迟分量**同一批**跨核 SEM 等待上（+78.37us）⇒ 合计上界 = **max(延迟侧, 工作消除侧)** = 1.10×/1.16×，而非两者之和。给出不可相加的论证是判决文书的必备部分。

### 3.5 缩块/调用数×N 类：固定段税预算带

tile 减半 ⇒ 原语调用数×2 ⇒ prologue/epilogue/flag 簿记/发射税是**线性税**，实施前不预算会 EV 高估：

1. 从既有 op 数据用差分法分解每调用固定段成本（scalar_t/调用数 或 A/B 形态对照）；
2. 给出税预算带 [下界, 上界]，EV 报告**名义/净双口径**（r13：名义 −10~15% → 税带 [+33,+101]us → 净 [−4,−16]%；实测 +74.9us 落带内中上段、wall −9.06% 落净 EV 中值）；
3. 净 EV 下界 < 采纳门 ⇒ 立项前降档或否决；
4. 采纳后强制重判 pacing 管身份（§2.6——固定段税可能迁移墙）。

### 3.6 复合模型项下钻（G-8）与静态审计单向性（G-9）

- **G-8**：引用 roofline/预算模型的任何**聚合项**作为候选 EV 依据时，必须逐项拆解到「该手段实际能攻击的加数」，以该加数（而非聚合项）对照采纳门；无关加数占比 >50% 时显式标注攻击面错配风险。反例：据「ramp ≈15%（134us）」立项 q_l1 双缓冲并宣称 EV −3~−7%，而模型自身算术显示 Q 切片仅 6.74us = ramp 的 5.0% = wall 的 0.78%，**85.2% 是与缓冲深度无关的通用流水填充项**——测量之前就已低于采纳门（iter24）。
- **G-9**：静态预算/编译合法性审计**超限可直接 NO-GO（判决力充分），过门不足以 GO**——容量合法 ≠ 编排合法 ≠ 可实现。凡「过门」结论必须显式标注「该形态从未编译/运行过」，不得作为可行性证据。反例：bN=256 scoping GATE1-5 实编全 PASS（L0C/L0B 双 64.00K「顶格合法」），实施后全形状族 HANG（§4.4）；compile-only 探针 4/4 COMPILE_OK 只覆盖 4 槽，生产需 8 槽（会话 9/10、iter26）。

### 3.7 矢量宽化/V 侧指令削减类：税种判别

「矢量计算碎片化 → 宽化/合并可削减」的模型只对了一半，立项前必须先做**税种判别**：

1. 用 op 模式把 V 侧时间分解为 **vec 主体**（= 数据体量 × 吞吐）vs **scalar/stall/wait 侧事件税**；
2. 事件税占比高且 vec 主体小 → 宽化 EV 为正；**vec 主体主导（如 case7 77.5% aiv）→ 宽化/削减类 EV≤0**，改攻数据体量或结构类手段；
3. CV 耦合环中 V 侧非 pacing 时，指令削减/宽化类手段**必须同时改变环耦合结构**（批深/协议窗/交接次数/交付节拍），否则 EV 预登记 ≤0、不立项。

三次同族实判（结论：**V 侧指令量对 wall 双向非绑定，环耦合结构才是绑定约束**）：

- r9-1 VW=2 宽通道：事件税侧签名**全部兑现**（v_scalar −11.7% / v_stall −35.6% / v_mte3 −27.9% / wait_id0 −44.2%），但 V.vec 主管道 +21.8%（634→773us，宽化引入大 repeat 执行低效 + always-on mask）吞没全部节省，wall 反向 +12.41%/+16.04%/+14.35% → 回滚；
- r14 指令融合（cast 直连 + fill/add 合一）：A/B BITEXACT 54/54、IR 普查证实落地（copy_ub_to_ub 恰 −1/shape ×20 形）、机制主签名命中预登记带（aiv_vec_time −3.82%），但 wall +1.07%（p=0.00121 显著劣化）——V 管削减 1:1+ 转化为跨核等待重暴露（aiv_wait_id0 +60%），并经环耦合把 C 侧标量阻塞同步拉高（**AIC IR 逐字节 20/20 不变的前提下** c_scalar_t 仍 +10.1us，纯环重定时耦合）。转化率 −19.8%；
- r7-1 w1 dtype 瘦身（字节削减）：机制激活但 wall 零响应（+0.31%/+1.16%），被 C mte1_stall +33us 1:1 吸收。

配套口径：**发射当量检查在削减型手段上方向不定**——指令融合可把静态偏移寻址迁移为运行时偏移寻址，每槽净减 1 条指令的同时发射当量反升（r14：+1.53%，而 IR 普查证明改动确实落地）。削减型的激活判定必须以 **IR 指令族普查（逐 family Δ 计数）+ 真实工作管计数器**为准，发射当量仅作寻址迁移归因用（核对被融合指令的源/目的偏移是否由静态转运行时）。消融型则相反：当量期望恒定，违例即探针污染。

## §4 机制定律库（Step 3 判断先验）

每条含：陈述 → 证据 → 边界。定律是先验不是免检牌——新算子引用时仍需 §3 的探针验证，但先验能决定候选排序与 EV 预估。

### 4.1 吸收律（CV 耦合闭环第一定律）

**陈述**：耦合平衡（双侧互等）流水结构下，**单侧吞吐类手段（加速/减字节/削指令）会被对侧等待 1:1 吸收，wall 零响应；交接结构删除类手段不被吸收**——双侧等待同时下降且真实工作管全平，wall 净收益兑现。

**证据**（四次定量实证 + 一次反例）：r7-1 加速 V → C mte1_stall +33us；r7-2 加速 C-G1（靶心 −54%）→ wait_id2 +68%；r8-1 L0B 槽深前瞻 → wait_id2 −24.3% 而 wall +0.23%；r9-1/r14 见 §3.7。反例 flat 槽流：wait_id5 −97.5%、wait_id2 −31.9%、wait_id4 −42.6% **三处同降** + 真实工作管全平 ±1.7% + wall −8%（会话 7/8/9/14）。

**边界**：前提是「双侧各有大等待余量」的耦合平衡态。若某管已是无等待余量的吞吐墙（pacing 管 busy >85-90% 且对侧无大等待），削减该管真实工作**是**有效杠杆（§2.2 减速侧对照可判定）。吸收律转化率定量：wait 读数高估 6.8~9.4×（延迟侧）/ 64.8~844×（工作消除侧）（§1.4）。

### 4.2 pacing 身份分域

**陈述**：同一算子不同 shape 域的墙身份可以完全不同，**禁止跨域混用/外推归因与手段**。

MHA 三个已定域：case9（D=256 大 prefill）= C↔V 四相位交接延迟链（批深摊薄不足）；case7/8（D=128 大 prefill）= AIV VEC 77.5%（不可削减真实计算）；decode D=128 = 布局突发物理墙（§4.12）。r13 后 kv_db 域 = scalar 固定段地板（§2.6）。对某域有效的手段换域前必须重新归因（iter24-26）。

### 4.3 黑盒原语稳态守恒律（及其可破性）

**陈述**：黑盒计算原语（gemm_v0 类：调用边界自带管级 prologue/epilogue 排空 + 内部每-step `PipeBarrier`）主导的循环里，**每槽稳态 wall = 黑盒内部常数（MTE2 字节时间 + 每 tile 标量阻塞），与外部 L1 槽数无关**——外部多缓冲/预取不改变它，EV 先验 ≈0，且可能引入净负副作用（§4.7 重排税）。

**证据**：r11-1 decode D=256 K 侧 L1 双缓冲，精度门禁全过、性能 +2.00%/+2.70% 劣化；duty 签名不动（68.45→68.89%）、三管精确零变化、同字节 MTE2 busy 速率反降 2.7%（会话 11）。

**边界（重要修正）**：守恒律是**「当前模板实现（prologue 管级 Set+Wait 自排空）+ after-return 发射点」两个条件的联合属性，而非硬件或原语本质**。破解三要素（会话 12 A10 实证，case15 −8.76%、duty 68.3→73.7%）：

1. 模板侧 opt-in：prologue 改 `WaitFlag<MTE2_MTE1>(调用方 id)`、不自 Set（解除「排空收编」）；
2. **发射点前移到 pre-call**：下一槽操作数预取在本次调用**之前**发射才能获得整槽流式窗口——after-return 位即使配 per-buffer 同步也时序中性；
3. FIFO 前缀旗标：Set 置于该消费点全部操作数 copy 之后 ⇒ 单旗标按发射序覆盖多笔装载。

**归档纪律**：黑盒域缓冲类候选的关闭结论必须写成三段式——(a) 守恒律成立条件（模板同步语义 + 发射点位置，逐项列明）；(b) 规则内不可压缩声明；(c) 框架级升级路径（§8）。「零响应/劣化」归档必须区分**域特化吸收**（可复活：换 régime 重评）与**黑盒结构守恒**（不可复活：除非黑盒被改造），并写明判别证据——MHA 曾因把守恒律误归因为「prefill 特化吸收」而错误复活候选，r11 实测劣化（会话 11 教训）。

### 4.4 bN 上界定理与 L0B 生命周期毒化

**bN 上界定理**：手动 mma 流水的 block_N 上界 = **B 操作数在途工作集（含 K-split 链全部在途 chunk）≤ L0B 64KB**。bN=256 ∧ D=256 ⇒ K^T/V 各 128KB = 2.00× 超限 ⇒ 相位内 L0B 重用不可避免 ⇒ 落入毒化域。设计期一行手算可拦截；**运行时表现为无报错挂死，不可调试挽回**（会话 10，15 变体毒化矩阵判决）。

**L0B 双重毒化**（症状均为 aicore timeout 挂死、无 core dump、静态令牌审计平衡仍挂）：

- (a) 相位内 L0B 槽覆写且释放边际 ~0-100ns：M 管 `SetFlag<M_MTE1>` 在 mma 退休点触发，cube 对 L0B 的物理读排空**滞后于退休信号**，立即覆写触发硬件级停滞。「延迟释放」变通无效（52-104ns 裕量仍挂；扩至 0.3-0.8us FIX 排空边际仍挂——E13/E21 双证伪）；
- (b) 同相位 K=128 mma 深度 ≥3 或 B 操作数二次读取（E17/E21/E15/PROD 实证）。

**已证安全谱系**（v4ksp 形态）：≤4×K64-mma/相位 + 分立槽 load-first（每 burst 专用槽零相位内重用）+ B 单次读取。生产先例的跨槽重用之所以安全，是靠下一槽 MTE2 到达 ~0.5-1us 的天然门控。B 工作集 >64KB 的 GEMM 必须走 gemm_v0 黑盒（内部编排已验证）或降 bN/kL0 使工作集入限。

**GATE 序**：工作集门**先于**槽容量门——分配声明 ≤ 池上限的「容量 PASS」不构成可行性证据（§3.6 G-9 同源）。

### 4.5 L0 池顶格域的相位纪律

当某 L0 池已被单相位在途工作集**顶格占满**（以生成 IR 的 `InitBuffer` 读数为准，不以源码 shape 手算为准——MHA 四实现 L0B 全部 `InitBuffer(ascend_l0b, 65536)` 逐字相同 = 100.0% 顶格），多相位共池的合法性**完全依赖相位串行时分复用**。因此「让两相位 iter/chunk 级交错以提升重叠度」不是可调优项——它把在途工作集按并发相位数**成倍放大**（交错需 8 槽 = 128KB = 2.00× 硬限）。立项前用一行手算拦截：**并发相位数 × 每相位在途 chunk 数 × chunk 字节 ≤ 池容量**。同时核对事件 id 预算（`EVENT_ID_MAX = 8`，每个有向 pipe 对独立计数；MTE1↔M 常是瓶颈——生产几何 8/8 零余量）。此类约束应在设计文档中记为**硬约束**而非「待解禁的约束」，避免被后续会话反复当作候选评估（iter26 GATE A）。

### 4.6 预取/多缓冲的适用前置三项核对

预取/多缓冲**不减少 GM/L2 字节总量**，只藏延迟。实施前核三项，三项全空 → 跳过该族手段：

1. **pacing 管识别**：wall 由 FIXP/MTE 吞吐或带宽墙主导且该管 busy 已 >85-90% ⇒ 藏延迟类预期零收益（case6 C 侧 FIXP 92.38%、case14/10 C FLOWCTRL≈0 纯吞吐墙）；
2. **装载段结构**：背靠背带宽串行单段 = 无 flag 空隙可挤，双缓冲不减 pipe busy（case1 C MTE2 单段 3050.8ns 无空隙）；
3. **冗余字节计量**：同址重读字节数 >0 才存在「减字节」类杠杆——此时优先考虑驻留/复用而非预取（注意：MHA 的 K/V 同字节冗余消除尝试 #R5-3 因条件跳过 DMA 的令牌协议陷阱产生非确定性损坏而回滚——「减字节」与「藏延迟」是两类手段，且条件化 DMA 必须 wait+set 同进同出，见 §2.5）。

MHA「MTE2 预取/L1 多缓冲」提案族在全部四条路径形态实测收口（#R3-2 +0.5% 噪声 / #R4-2b 全 pipe 逐位不变 / #R6-2 真机零收益 / #R11-1 劣化），四次失败共享同一判定结构（会话 3/4/6/11）。

### 4.7 重排税及其符号条件

带宽墙域（busy 已贴布局上限）的 MTE2 流重排具负外部性：同字节 busy 速率 −2.7%（DRAM 页局部性被破坏），吞没边界先导收益（r11 after-return 交错实测）。**符号条件**：交叠若伴随间隙消除 ⇒ 税可为正/零（r12 pre-call 流式 +1.1%）；纯交错无间隙消除 ⇒ 负。凡预取/重排类候选，采集**同字节 busy 速率**作为重排税签名，与 wall 分开报告（会话 11/12）。

### 4.8 CV-over-GM workspace 的 L2 事实

AIC/AIV 经 GM workspace 交互时，往返**物理上是 L2 往返而非 DRAM 往返**：生产态写命中 98.26%、读命中 99.9989%、miss 绝对数 0.55（iter26 实测）。推论：

- 「削减 workspace 段数/dtype 可省 XX MB DRAM 流量」类宣称价值 ≈0（MHA 曾宣称「省 1032 MB / 46% L2 流量」，消融实测工作消除侧转化率 0.12-1.54%）；
- **写侧不可单独移除**（为读侧提供局部性，§3.4 WE-6）；
- workspace 削减类候选的 EV 必须按 L2 介质核算（§1.6/§1.7），不按 DRAM。

### 4.9 flat 槽流收益模型（交接结构删除类的 EV 预估）

**收益 ≈ f(批深空缺率, 任务边界密度)**——空缺率 = 1 − 运行期平均批深/标称 NUM_STAGES；边界密度 = 任务边界数/核。五点校准（会话 8，同机制）：

| case | 收益 | 结构参数 |
|------|------|----------|
| case2 | −33.1% | eff 1..2 → 每任务 1-2 槽微批，空缺率最高、协议轮 ~6→~2 |
| case3 | −21.6% | 同族 |
| case4 | −20.7% | 同族 |
| case9 | −8.1% | eff 均值 4.5/8 半空转 + 边界 103→~58/核 |
| case7/8 | −7.4%/−6.3% | 边界密度最低 |

收益来源 = **排空点与任务边界耦合的删除**（批轮次 ~103→~58/核、批深 4.5→8），**非** SEM 轮数削减——见 §4.10。

**两参数的操作性估算法**（无需实测即可立项预估）：① 名义批深 = 源码 NUM_STAGES 常数；运行期平均批深由 shape/causal 几何**静态推导**——`eff_kv_iters(task)` 是右下对齐公式的编译期可算函数，对任务分布求均值后按 NUM_STAGES 截断（MHA case9：eff 均值 4.5 / 名义 8 ⇒ 空缺率 44%）；② 任务边界密度 = 每核任务数（host 分派的 `my_count`）÷ 每核批轮次（≈ Σeff / NUM_STAGES）。需要实证时用 camodel 批头标记计数（定性）或探针 printf 采样批深分布。两参数代入后按五点校准表内插出 EV 先验带。

实现机制（运行期非均匀 trip-count 的顺序游走状态机、双侧同式计算、批头快照重走、前缀表否决判据）见 `examples/mha/perf_tuning/optimization_log.md` [IMPL-#R8-2]，属 flash_attn_optimize.md §1 批量流水的推广形态。

### 4.10 协议税坍缩（收益不可叠加律）

同步协议优化的收益会**互相坍缩**：`barrier_all` 纯移除 15 处（#R4-1，依赖 gemm_v0 自平衡 prologue/epilogue + 跨核 SEM 全覆盖）使每轮 SEM 开销从 ~3.6us 坍缩到 ~0.25us ⇒ 此后「削减协议轮次」类手段收益归零——#R4-3 扁平批处理 decode 推广 6/6 噪声带回滚（会话 4）。**立项任何同步类候选前，先确认它攻击的税种没有在先前优化中已坍缩**；EV 模型必须以当前实测协议开销为准，不引用历史归档值。

### 4.11 stall 读数伴生症状定律

`scalar_mte1_stall` 等 stall 类读数**只指示位置、不指示收益**，直接攻击它通常无效：r8-1 直接攻击 mte1_stall 436us（L0B 前瞻深度 0→2，位级全安全），stall 仅 −2% 且 wall 零响应；反之 flat 落地后 stall **上升** +14.7%（434→498us）而 wall **下降** −8%——stall 是「scalar 更早到达装载等待点」的位置信号（生产性 pacing 重分配）。两次相反方向实证构成完整判读：stall 列为攻击对象前必须满足 (a) 单侧 A/B 排除完成，或 (b) 该管为 pacing 管（§2.2）。「stall > busy = 纯延迟暴露可攻击」是耦合结构下可证伪的启发式（会话 8）。

### 4.12 布局突发墙（BSHD 行跨步访存）

行粒度不足的字级跨步访存存在**布局突发物理墙**：256B 行/8KB 跨步（= BSHD D=128 fp16 逐行装载的生产形态）单核 56.3 GB/s（4.4× 突发惩罚）、20 核聚合上限 966 GB/s；512B 行即恢复 99%（1452 GB/s）；惩罚在 L2 驻留态仍在（142.6 vs 253.9 GB/s）⇒ 事务级 + DRAM 页双重机制、非线性阶跃。**任何实现（含 CANN baseline）都受此墙**（baseline case11 同墙 894-939 GB/s）——「D=128 无带宽魔法」。生产每槽 wall 94% = 上限的算术必然时，剩余空间 ≤6-8%，别再立项「带宽对齐」类候选。对策方向是改布局（行加宽/转置驻留）而非改调度（iter24-26 分析轮，微基准矩阵 `/tmp/opencode/decode_roofline_a1/` 方法可复制）。

### 4.13 位级等价免探针知识

- fixpipe RNE ≡ V 侧 vcast RNE（11/11 BITEXACT，会话 3）⇒ L0C→GM 直写替换 vector 输出链免位级探针（仍需切片/尾块行为探针，§5.1）；
- gemm_v0 `init=False` 跨调用 K 升序链式累加 ≡ 单段（BITEXACT，强于值级接近；会话 11 门①）；
- 单 mma k=256 ≡ 链式 2×k=128（位级等价，会话 4）——但 kNumSteps=1 会关闭 L0 ping-pong，**位级等价 ≠ 性能等价**（r4-2a 劣化 +3.7% 回滚）。

## §5 实施与守卫工程（Step 4/5 采纳门）

### 5.1 精度门分层

| 变更性质 | 主判据 | 说明 |
|----------|--------|------|
| 调度类（批处理/flat/槽旋转/预取位/同步语义，数值路径不动） | **vs 改前态 BITEXACT**（探针域全 BITEXACT + 位级锚） | 位级等价是调度变更的强守卫；出现任何 DIFF 即实现有 bug，不存在「误差可接受」的说法 |
| 数值类（tile 尺寸/dtype/归一化次序变更） | **阻塞口径**（混合容差 + MARE 门） | 非 BITEXACT 是预期，按设计文档的精度标准判 |
| 极端值域/饱和域形状 | **双判据**：vs_old BITEXACT 为主 + golden 阻塞口径为辅 | golden 超阈时先做旧核同数据归因（同值 → 既有伪影入库不阻塞）。实证：valrange 探针 MARE 1.36 超阈 = CPU-fp16 golden 在饱和指数域的固有伪影（旧核同数据 matched=0.99924 同值）；探针形状选型优先 D=256 或降 scale/value_range 避开饱和域 |

**假阴性陷阱**：静默损坏类探针**必须用非零数据**——全零输入下 K-only 损坏变体探针「通过」（case20 全零假阴性），真实数据 6/6 全 DIFF（会话 5）。位级安全 ≠ 性能达标：采纳判据始终是性能规则（r11-1 探针 22/22 BITEXACT 仍因 +2.0% 回滚）。

### 5.2 IR 逐字节守卫集（两级口径）

守卫 shape 集（覆盖全部分派域 + 边界形状，MHA 用 16-20 个）在改动前后 dump 生成 IR 逐字节比对：

- **C1 字面投影**：目标域 IR 逐字节相同——最强证据，「19/19 非目标域设备码与改前构建逐字节相同」使未触及域的 bench 数字可直接沿用；
- **C2 计算语义投影**：V 侧改动移动 V 专属缓冲首用序时，codegen 的 UB 存储规划器按首用序重排共享序言中的视图（`ascend_ub.GetWithOffset`），地址重排**波及 AIC 投影文本**——字面级全灭但计算语义零触碰可独立证明。缺语义分级门时合法改动会被字面门误判「越界」而错误回滚（r14 判例）。判定方法 = UB 布局审计（逐 buffer 首用序 + 偏移对照）+ 计算指令序列投影比对。

守卫集的三重用途：越界检测（改动泄漏到非目标域）、回滚验证（§5.5）、bench 数字沿用资格。

### 5.3 压力/探针门的路径覆盖核对

**继承自上一轮的压力配置可能全部打在旧路径上，对被改分支零覆盖，给出 PASS 的假安全感**。实证：继承的 R11 压力 4 配置经核查全部落在 generic/Form B 路径，完全不覆盖本轮新增的 Form A 单块批处理分支；另写 7 配置 ×12 复跑专打新分支（batch_tasks=1/2/5/6/7/8、跨轮、分池、双 dtype、causal、双尾块、非齐次 my_count）才真正验证（nondet=0）。

核对方法：用 `get_kernel_source()` diff 定位新增分支的触发条件/谓词 → 反推能命中该分支的 shape/参数组合 → 核对现有测试矩阵是否包含这些组合；不包含则新增专门配置后才进入采纳判定（会话 5）。竞态压力矩阵的标准维度：槽轮转 / 跨轮 / 任务边界 / 奇偶批 / 双槽尾块 / 掩码翻转 × ≥12 次重复，nondet=0。

### 5.4 JIT 缓存纪律

tilelang JIT 缓存键**不覆盖 annotation 级源变更**（如 `annotate_layout` 调整）⇒ 两类事故：

1. **假复现**：修复后 A/B 运行命中陈旧产物、逐位复现修复前读数（rev4-attempt1 两轮中招）；
2. **污染条目**：调试期旧源与当前源同 cache key，默认缓存中长期留存毒条目，锚复跑命中后产生**确定性** DIFF（1.305e-01），易被误判为 kernel 回归（会话 7 收口补录：检出 → 隔离缓存判别 → 缓存内 kernel.cu md5 与当前生成码字节级比对定位 → 清除 → 清洁缓存复验锚 10/10）。

纪律：验证与 A/B 一律 `disable_cache=True` 或会话专属 `TILELANG_CACHE_DIR`；「来源不明的确定性 DIFF（隔离环境通过、默认环境失败）」优先怀疑缓存污染而非 kernel 缺陷。

### 5.5 回滚三重验证

回滚不是 `git checkout` 完事，必须三重验证：**md5 逐字节 + 行数一致 + IR 守卫集全量逐字节还原**（16/16），再跑轻量复验（l0 + 锚 + smoke）。回滚验证与采纳验证同等级——「净变更 = 0」本身是需要机器证明的结论（会话 9/10 判例）。

### 5.6 中断恢复纪律（provenance 核验法）

长调优会话被外部中断（实施+门禁完成、采纳判定未落档）后，恢复者面临两难：误信不可溯源的日志，或保守全量重跑浪费小时级预算。正解：

1. **基线链核验**：kernel md5 × 备份链 × 落档记录三方一致；
2. **IR provenance 核验**：当前源新鲜 dump（disable_cache + 专属缓存目录）与门禁时 IR 参照逐字节比对——**一致 ⇒ 全部已验证门禁（探针/双锚/压力/l0/l1/coverage）零重做复用**；不一致或参照缺失 ⇒ 重跑关键门禁；
3. **缺口清单法**：从 optimization_log/perf_log 尾部对齐「已完成/未落档/未开始」三栏，只补未落档与未开始项；
4. **探针伪影对账**：首跑 FAIL 记录 vs 有效判定 PASS 落档的差异须双判据独立复核后才可沿用；
5. 恢复注记落档（provenance 结论与对账过程如实写入 RESULT 条目）。（会话 8 中断恢复实证，16/16 逐字节一致零门禁重做）

| 10 | `pkill -f` 模式串出现在自身命令行 → 自杀；occurrence 计数器内层循环重复自增 → 双插入错位 | bracket-trick；先物化 occurrence 列表再映射 |

### 5.8 kernel 计算体的代码组织形态

纯 Python 闭包（closure/lambda/间接函数层）内的 `T.*` 发射会被 TVMScript parser **静默丢弃**——编译「成功」、无任何警告，生成码缺失该层全部指令，运行期孤立 `WaitFlag` 死等挂死。计算体组织只有两种安全形态：**逐字内联展开**或 **`@T.macro`**。冒烟验证必须核对**生成码内容**（目标指令存在性），「编译通过」不构成发射完整性证据（rev4 Form B-mma 首跑挂死判例，`smoke_fbm_src.cc` 铁证：C-scope 只剩 caller 层指令）。

## §7 候选治理与关闭纪律（跨会话）

### 7.1 候选状态机

```
active → adopted（>3% + 全门禁）
       → rolled_back（性能规则：无变化/下降/精度失败/运行失败）
       → closed_by_evidence（证据性关闭：零响应族/机制证伪）
       → closed_structural（结构性不可行关闭：穷尽条款 + 静态证明族）
       → revived（前置条件实测满足时零探针成本复活，§7.3）
```

**证据性关闭**必须附：判决数据 + 关闭形态（机制证伪 / 吸收律 / 零响应）+ **重试前置条件（可观测判据）**。实证：w1 瘦身关闭条件 =「FIX 成 pacing 才重试」；② 槽旋转 =「MTE2 管收缩才复活」；③ 宽化 =「bN≥256 行体量摊薄 repeat 税」。前置条件使复活判定成为机械操作而非重新论证。

### 7.2 关闭形态三分法与最小证据链

| 形态 | 判据 | 最小证据链 |
|------|------|-----------|
| 性能规则回滚 | 噪声带内/劣化 | msprof A/B + IR 回滚三重验证（§5.5） |
| 证据性关闭 | 机制激活但 wall 零响应/反向 | 机制签名读数 + 吸收/迁移计数器 + 转化率（§1.4） |
| 结构性不可行关闭 | 硬件定理级 | 预登记穷尽判据命中 + 静态不可能性证明族 + 变体矩阵全留存（§2.4）；**穷尽条款 = 永久禁止该形态族重试**（MHA：任何 bN=256@D=256 手动 mma 重试被永久否决） |

### 7.3 负结论归档三字段（时代对照）

负结论归档必须区分「结论的前提依赖」，否则时代性负结论会被误存为永久负结论。强制三字段：

1. **前提清单**：该负结论依赖的每条机制事实，逐条引用证据编号；
2. **失效触发器**：何种未来结论/机制变更使哪条前提作废；
3. **推演负/实测负分级**：推演负 = 弱结论（复活门槛 = 前提复核即可重试）；实测负 = 强结论（复活门槛 = 前提废除 + 新机制证据）。

**完整闭环实证**：S1（kv_db bN=128 双侧 DB）在 r11 被推演性关闭（三链：gemm_v0 守恒律 + 协议税 + 重排税）→ r12 框架改造**废除其核心前提**（守恒律 = 管级 prologue 属性，opt-in 后不成立）→ r13 复活实测 **−9.06% 采纳**（duty +12.9pp）。反向对照：同轮被否的 S3（region 切片路线）前提 = 前端能力缺陷，未因框架改造失效 ⇒ 保持关闭。**任何采纳新机制的会话，收口时必须扫描在案负结论库、按失效触发器机械核对复活窗口，产出「移交候选队列」**（会话 11/12/13）。

### 7.4 结构类候选失败治理

结构性变更（rev 级工程）立项时强制预登记：**失败判据 + 方案数上限 + 终局实验定义**；判决 = 判据机械执行，**禁止临场加试**；知识资产留存清单纪律（变体全文件 + 判决日志 + 生成码 dump）。对照：会话 9（③ 族三签名判据预登记）与会话 10（T1 穷尽判据预登记）双双零漂移收口。

**负 EV 验证不实施**：机制级证伪跨域成立 + 目标域 EV≤0 预判 ⇒ 直接跳过实施、落档裁决依据（[STAGE2-RULING] 形态），预算转投剩余候选——任务书/计划的字面执行让位于数据驱动裁决（会话 8/9 两度复用）。

### 7.5 收口判据

触发任一即收口：① 迭代达上限；② 连续 3 次无 >3% 提升（中止条款）；③ 版图收束——全部候选族处于 adopted/closed 态且复活窗口未开（MHA 会话 10 判词：「① 已兑现、② 证据性关闭、③ 规则内永久关闭、路径 2 结构性不可行 ⇒ 仅剩架构级方案」）。收口时如实登记：权威分数链、每 case 终态、已知差距与归因、未验证项。**收口不是失败——EV 版图闭合并把「剩余差距规则内不可达」证明清楚，与采纳一个 −10% 同等有价值**（iter24-26 三轮零采纳收口即此类合格产出）。

## §8 框架级改造通道（算子内手段穷尽后）

### 8.1 适用判据

瓶颈实体位于框架模板/helper（如黑盒原语的同步语义），且算子侧手段已被守恒律类证据关闭（§4.3 三段式判决的 (c) 项）。这是最后一条通道，不是首选。

### 8.2 通道选型三模板

| 通道 | 形态 | 判据 |
|------|------|------|
| **(b) header-only 默认模板参**（首选） | 模板加默认参（`int32_t kXxx = -1`）+ `if constexpr` 分支 + 前端条件拼接 kwarg，**零 C++ rebuild** | 目标原语的设备调用串为**前端 f-string 全文拼接、codegen 透传不解析**形态（用 dump 生成码 + 前端源码双确认；gemm_v0 实证）；opt-in 行为扩展 |
| (a) 全链 plumb | 前端 + op attrs + codegen + rebuild | 需要 lowering/transform 感知的语义变更；爆炸半径大 |
| (c) 调用方绕过 | call_extern 等 | 通常否决——丢失框架的 pipe 标注（如 PIPE_M operation_config） |

### 8.3 采纳门：默认路径逐字节不变的四重证明

框架级 opt-in 改造的采纳门（缺一不可）：

1. 守卫 shape 集 IR dump 逐字节相同（17/17）；
2. 前端模板串拼接逐字符核验（旧调用生成串与历史形式逐字节相同）；
3. `if constexpr` 编译期折叠论证；
4. **非目标消费者 UT 真机回归**（gemm_v0 4 件 UT 90/90 passed）。

配套纪律：

- **生效链核查**：JIT include/模板路径解析实测（tilelang env.py 的 install/develop 双回退使源码树改动直接生效；pip wheel 分发需重打包）+ 评测/分发环境各自确认，禁止假设（会话 12 实测证伪了「wheel 重装前置」的预设）；
- **成对提交**：框架 + 算子变更必须绑定同步/分发，单侧提交 = 收益丢失或行为分裂；若成果需要框架补丁才能兑现，**提交口径必须披露**（stock 态性能单独实测并如实标注，参照 `examples/mha/PR_DESCRIPTION.md`「stock 框架口径披露」节）；
- git 纪律：diff 全文落档、改前备份框架文件、**禁 commit 除非用户明示**。

### 8.4 核内事件旗标硬约束（Expert 同步设计前置知识）

- 核内 `SetFlag/WaitFlag<HardEvent>`（ISASI）：**id 0-7 共 8 个；静态 Tensor 场景 id 6/7 禁用；Set/Wait 必须成对**；黑盒模板独占 id（gemm_v0 的 L0AB_EVENT 系）须避让。
- 与跨核 `CrossCoreSetFlag` 的「同一 flagId ≤15 次未消费 set」约束**分列**——两者曾长期混淆（§3.3 第 2 条）。
- 旗标是 1-bit 还是计数器语义**无文档明文** ⇒ 设计纪律 = **按 1-bit 最强假设自约束**（每 id outstanding ≤1、严格 1:1 Set-Wait 交替）⇒ 对双语义免疫。
- **FIFO 前缀旗标组合模式**（id 预算紧张时零新增满足多槽 DB）：单 id 的 Set 置于其消费点**全部**操作数 copy 之后 ⇒ 按发射序覆盖多笔装载（一旗覆盖 V+P）；Set 之后发射的 copy（下一槽预取）天然不入前缀。消费点操作数集变化时（如 bN 变更）前缀边界必须重审（会话 12/13，双侧 DB 总占用 3/6 零新增，压力 19 配置×12 nondet=0）。
- `T.set_cross_flag` 生成的 `CrossCoreSetFlag<mode, PIPE_x>` **阻塞至 PIPE_x 排空**（兼具跨核信号 + 本核 pipe 隐式定序双职责）⇒ 与 `wait_cross_flag` 必须成对增删；性能归因时其开销计入对应 pipe 的排空而非泛化「同步开销」；`wait_cross_flag` 的 pipe 参数仅 A5 支持，910B/910C（A2/A3）必须单参调用。
