- **target_skill**: tilelang-perf-optimization

- **target_section**: SKILL.md 性能数据采集命令（`msprof op` 口径处）
- **type**: unclear_workflow
- **severity**: medium
- **status**: pending

**Observation**:
SKILL.md 只给了 op 模式的 `msprof op --kernel-name=... python xxx.py` 命令，未覆盖 simulator 模式流水图采集——而流水图（相位重叠/交接气泡定位）正是 sync 类瓶颈定性的关键证据源，本次任务即由用户显式要求采集流水图。

**Evidence**:
本次实操：`msprof op simulator --soc-version=Ascend910_9362 --kernel-name=main_kernel --output=... python3 examples/gqa/prof_gqa_pipeline.py` 成功产出 `OPPROF_*/simulator/trace.json`（Chrome trace 格式，29744 事件，含 SET_FLAG/WAIT_FLAG 与 flow 依赖边，chrome://tracing 可直接加载）。关键约束：传错 soc-version 时报 `--soc-version is invalid, please specify a simulator in $ASCEND_HOME_PATH/tools/simulator`——必须与该目录下已安装仿真器名精确一致（本机芯片名可由 `torch.npu.get_device_name()` 获得，本例 Ascend910_9362）。另有 WARN：kernel 未带 -g 调试信息时无源码级调用栈（不影响指令级流水图）。

**Proposed change**:
在采集命令章节增加 simulator 流水图小节：命令模板、`--soc-version` 与 `$ASCEND_HOME_PATH/tools/simulator/` 目录精确匹配要求、产物结构（聚合 trace.json / visualize_data.bin / per-core instr_exe.csv）、chrome://tracing 与 MindStudio Insight 两种查看方式、-g 缺失的影响说明。

**Proposed change**:
troubleshooting 条目：症状（bisheng 'unexpected type name int32_t'，调用栈不指向根因）→ 原因（if_then_else/condval 多语句模式流入表达式位）→ 解决（T.alloc_var 语句位绑定后再传宏/索引），并注明该报错具有误导性、优先排查索引表达式中的条件表达式。
