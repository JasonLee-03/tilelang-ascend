**Observation**:
`source set_env.sh` 会把仓库根加入 PYTHONPATH，导致未编译的 in-repo `tilelang/` 遮蔽 site-packages 已安装版本，任何依赖已装 tilelang 的脚本（如 `examples/{op}/test_{op}.py`）直接 import 失败——环境预检本身是 PASS 的，这个坑只在"按惯例 source set_env.sh 再跑测试"时触发。

**Evidence**:
第一手复现（2026-09-12，仓库根）：
`bash -c "source set_env.sh; python -c 'import tilelang; print(tilelang.__file__)'"` →
`File ".../tilelang-ascend/tilelang/__init__.py", line 65, in <module> import tvm` →
`ModuleNotFoundError: No module named 'tvm'`（TileLang:tilelang.env:WARNING: TVM is not installed or found in the expected path）。
而 `unset PYTHONPATH; export ACL_OP_INIT_MODE=1; python examples/gqa/test_gqa.py --level all` → 19/19 PASS（Orchestrator 同日二次校验）。

**Proposed change**:
troubleshooting 新增独立条目："source set_env.sh 后运行脚本报 `ModuleNotFoundError: No module named 'tvm'` → 原因是 in-repo 未编译 tilelang 经 PYTHONPATH 遮蔽 site-packages 版本；解决：`unset PYTHONPATH` 后直接运行（走已安装版本），或先完成 in-repo tilelang 编译再 source set_env.sh"。
