## Entry e1
- **target_skill**: tilelang-custom-skill/tilelang-api-best-practices
- **target_artifact**: troubleshooting
- **target_section**: 运行时错误.AUTO threads=2 下 strided UB→GM 写产出错误数据（AscendVidReduction 描述符缺陷）
- **type**: known_bug_avoidance
- **severity**: high
- **status**: pending

**Observation**:
AUTO（Developer）模式 threads=2 的 kernel 中，把输出 `T.copy(UB→GM)` 从连续布局改为 strided
（BSND 4-D 盒写）后，AscendVidReduction pass 生成的描述符错误：blockCount 未二分（64 而非 32/vid）
且 vid 偏移沿用连续布局旧值（vid*4096 应为 vid*32768）→ 两个 vid 重叠写 + 越界写，输出静默损坏
（非编译错、非挂死——逐位对比才暴露）。threads=1 流水形正确。所有 causal/奇数kv/D≠128 的
per-head 形必经 threads=2，规避面窄。

**Evidence**:
iter9 生成码审计 + 逐位探针双证据：r1 shape BITFAIL maxabsdiff=5.9e4、c5 shape BITFAIL NaN；
6 配置 base/w2 源码对拷，copy_ub_to_gm 计数两臂相等但 threads=2 形描述符错误
（`examples/gqa/perf_tuning/candidate_iter9_P2w2.json`、`p2_wave2_design_iter9.md`；
生成码 .cu 留存 perf_tuning/）。对照组：expert 模式同形 strided 写描述符逐项代数核对正确
（iter8/iter9 已产线采纳，13/13 + 17/17 逐位）。

**Proposed change**:
在 api-best-practices 的 troubleshooting（或 references/troubleshooting.md 新建条目）收录：
"症状：AUTO threads=2 kernel 改 strided UB→GM 输出后数据损坏/NaN（编译运行均正常）→
原因：AscendVidReduction 对 strided 写发出未二分 blockCount + 陈旧 vid 偏移 →
解决：strided 输出写改用 expert 模式 kernel（手动 vid 语义），或等框架修复；
上线前必须生成码审计（blockCount/偏移代数核对）+ 逐位对比，不能只跑通。"

## Entry e2
- **target_skill**: cann-bench
- **target_artifact**: troubleshooting
- **target_section**: 评测故障.精度阶段并发导致 Fixed-Core 跨核信号量 kernel 共驻死锁（aicore timeout 507014）
- **type**: runtime_error_recipe
- **severity**: high
- **status**: pending

**Observation**:
`run_evaluation.sh` 精度阶段默认 `--processes-per-card 2`：两个 blockDim=20 的 Fixed-Core
expert kernel（跨核信号量协议）并发共驻同一张 20 核芯片时，若调度器交错分派两 kernel 的 block，
各自 flag 链等待对方永不就位的对等 block → 共驻性死锁 → 设备看门狗 aicore timeout（507014），
首败 case 后级联 sync 失败、后续 case 被跳过，整次评测作废。该危害与算子代码正确性无关
（AST 对照 + 串行复现全过），是"评测并发 × kernel 家族特性"的组合 hazards；竞态窗口依赖
case 时长配对，历次评测可通过属时序侥幸——任何 kernel 提速都可能移动窗口触发。

**Evidence**:
2026-10-19 评测 attempt-1（`cann_final_eval_20261019_175412`，14/20 INVALID）：case 15
（decode d256，dense_expert_d256 blockDim=20）507014，case 16/17 级联、18-20 跳过；
设备 plog `debug/plog/plog-423741_*.log`：stream_id=45 task_id=29 errType=0x4 task timeout、
blockDim=20、retCode=0x25。排除代码回归的证据链：7/9 kernel 工厂 AST 与上轮评测通过版逐字节一致、
本地串行复现 + case15-20 顺序冒烟全过、同评测串行 stage 3 14/14 过、双进程并发压测未复现（概率性）。
处置：`--processes-per-card 1` 重跑 → 精度 20/20 零失败（两次：20261019_202123 / 20261020_144308）。
分数可比性：性能阶段历次均串行（"1 卡 × 1 并发/卡"），精度阶段并发度不进任何计时。

**Proposed change**:
cann-bench 文档（README 或 run_evaluation.sh 帮助/notes）新增故障条目："症状：精度阶段某 case
aicore timeout 507014 且级联失败/跳过，但同 shape 串行本地复现通过 → 原因：Fixed-Core
blockDim≥核数的跨核信号量 kernel 在 2 路并发下共驻死锁 → 解决：--processes-per-card 1 重跑
（性能阶段本就串行，分数可比）；建议在算子元数据中声明 co-residency 敏感属性供调度器自动降并发。"

## Entry e3
- **target_skill**: tilelang-perf-optimization
- **target_artifact**: skill
- **target_section**: references/best-practices（新增"aux 搬运 kernel 消除：BSND strided 直读/直写"模式节）
- **type**: missing_constraint
- **severity**: high
- **status**: pending

**Observation**:
skill 现有文档（flash_attn_optimize / optimization-guide / antipatterns）没有"用主 kernel strided
直读/直写消除独立 transpose 类 aux kernel"的模式记载，而这是 round 3 最大收益来源
（P2 输出直写 + P4 输入直读合计 e2e −13..−33%，11/20 bench case 变单 kernel 链，score +1.48）。
关键可行事实（全部实证）：(1) expert 模式 `T.copy` 对 BSND 视图盒的 GM↔L1/UB strided 搬运可表达，
lowering `compute_strideN` 自动折叠 singleton 维（realSrcN=D→N·D）；(2) ND→NZ 是 MTE2 **随路转换**
（Catlass TileCopyTla），无需 UB 中转；(3) strided 盒速率≈连续（MTE3 写 1.07-1.17×；MTE2 读差分
−0.47..+0.70% 无劣化）；(4) 生成码仅 dstStride/srcStride 参数变化、指令条数两臂相等——
使"main 吸收搬运成本 ≪ 被消除 kernel 的 TaskDur+launch 地板"普遍成立；(5) RAG 约束
asc_copy_gm2l1 n_burst≤4095、gap 32B 单位，盒参数需逐盒核对在界。

**Evidence**:
iter8（输出直写 BSND，wait-id 判别门证明不扰 pacing：Σwait 膨胀 ≤5% 收益）+ iter10/11
（输入直读，探针五证据链：lowering 源码 + codegen 审计 + decode dense_expert 产线先例
gqa.py:1228-1231/:1265-1268 + RAG + 微基准）。数据：`candidate_iter8_P2.json`、
`probe_iter10_P4.md`、`candidate_iter10_P4.json`、`candidate_iter11_P4w2.json`；
评测固化：cann_final_eval_20261020_144308（score 70.73，覆盖 11 case −6.0..−27.6%）。
边界：AUTO threads=2 kernel 输出侧 strided 写被 e1 所述 bug 阻塞（读侧未测）；
非对齐 shape 的裁剪/零填充语义留 aux 路径（fp16/bf16 d2d ViewCopy 561103 陷阱）。

**Proposed change**:
best-practices 新增模式节"aux transpose/pad kernel 消除"：适用判据（aux 为纯搬运、e2e 份额、
main 为 expert 模式）、实施要点（能力位+gate 逐域推进、生成码审计=指令数相等+描述符代数核对、
wait-id 判别门强制——装载/写回在 paced 环内）、排除面（AUTO threads=2 输出写、非对齐裁剪）、
经济学口径（收益 = aux TaskDur + launch 地板 − main 增量，tripwire ≤50%）。

- **target_skill**: tilelang-perf-optimization
- **target_artifact**: skill
- **target_section**: references/performance-antipatterns.md（launch/网格类关注项，扩展到 aux kernel）
- **type**: missing_constraint
- **severity**: medium
- **status**: pending

**Observation**:
antipatterns 的 launch 核数关注项（A/B）只盯主 kernel；**aux/搬运 kernel 的任务网格饥饿**未被覆盖，
而它是实测最重的单项税之一：transpose_out 在默认 shape 仅 1 任务 1 核（42.6 GB/s = L2 屋顶 1.2%），
12µs 超过 main 本体，aux 占 e2e 高达 61%。重铺 tile 使网格匹配核数后 e2e −26.8%（R1）。
另一实测新约束：**块波次开销 W_OH≈2.5µs/wave**——首版重铺规则用"多波小盒"配置在 R2 类
反而 e2e −16.8% 回归（被预注册护栏否决），改墙钟模型 `wall ≈ L + waves×max(W_OH, bpb/RATE)`
+ wave-first 平手 + 20% 迟滞后全过。小盒铺满核数≠最优，波次量化必须进选择规则。

**Evidence**:
iter6 B 矩阵 aux 分离数据（份额 R1 61.1%/R6 54.5%/R2 47.1%/R3 40.9%/R4 23.3%/R5 0%）；
iter7 V1（否决臂，数据留存 36 msprof 目录）vs V2（采纳）：R1 e2e 27.40→20.05µs，
tout 12.08→4.86µs（blk 1→16）；`candidate_iter7_P1.json`、`p1_retile_iter7.py`（含离线预测器）。
评测固化：20261019_202123 c1 −22.5%/c18/c20 −25.1% 等。

**Proposed change**:
antipatterns launch 类新增条目："aux/搬运 kernel 网格饥饿审计——对每个独立 launch 的 transpose/pad/copy
kernel 核对任务数 vs 核数（饥饿判据 tasks < cores），饥饿网格按墙钟模型重铺 tile；
模型必须含块波次开销（~2.5µs/wave 量级，本 SoC 实测拟合）并对健康网格加迟滞保护，
防止多波小盒配置反向回归；改动 host-only、输出逐位一致为硬门。"

- **target_skill**: tilelang-perf-optimization
- **target_artifact**: skill
- **target_section**: SKILL.md 测量矩阵设计（工况选择步骤）
- **type**: unclear_workflow
- **severity**: low
- **status**: pending

**Observation**:
性能测量矩阵若只取对齐 shape，会系统性漏掉 padding/tail 路径的巨额税：gqa 非对齐 skv200 的
tail-mode tqkv 实测 167-168µs、skv400g 289.7µs = 对齐同构的 **6-10×**（Fill+slice-assign 链内），
而 bench 20 例全对齐——该税对分数不可见却对真实调用方巨大。skill 的工况选择指引未要求
"对齐 shape 必须配非对齐同胞（isomorph）对照"。

**Evidence**:
iter9 附带实测（s100e e2e 235µs vs 对齐同构 57µs = 4.1×，`candidate_iter9_P2w2.json`）；
iter11 msprof 兜底再证（skv200 tqkv tail 167-168µs、skv400g 289.7µs，
`msprof_op_iter11_G3_*`、`parse_iter11_g3.txt`）。round 3 全部优化 gate 均排除非对齐域，
该税原样留存——已列 next_hint 独立立项，但发现本身依赖偶然附带测量而非矩阵设计。

**Proposed change**:
SKILL.md 测量矩阵步骤加一条："每个对齐代表 shape 应配一个非对齐同胞对照（同 D/同头数、
S 或 S_kv 偏 1-2 个 tile）；两者 e2e 差 >2× 即标记 padding/tail 路径税为独立候选项，
即使评测集（bench）全对齐——真实调用方分布通常含非对齐。"
