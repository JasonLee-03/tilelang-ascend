## Entry e1
- **target_skill**: tilelang-custom-skill/tilelang-api-best-practices

- **target_section**: "编译错误.use of undeclared identifier 'CUDART_INF'"
- **type**: error_code_workaround
- **severity**: high
- **status**: pending

**Observation**:
`T.reduce_max(..., clear=True)`（默认）在**部分 tilelang-Ascend 构建**（评测机
CANN 9.1 自建版）下 lowering 出 `Fill(m_i, -CUDART_INF)` / `Muls(acc_s_ub,
CUDART_INF)`——`CUDART_INF` 未定义（该版本 common.h 不含自包含宏），bisheng
编译失败；而 pip 0.1.4 版本用自包含 `#define CUDART_INF_F 1.0f/0.0f`
（tl_templates/ascend/common.h:19）编译正常——**同一 API 的 clear 参数在两个
tilelang 版本间一边编译失败、一边性能回归**（clear=False 在 0.1.4 的 lowering
给硬件 ReduceMax 包标量 GetValue/SetValue 备份合并循环，实测 kernel 1.65-1.8x
退化）。

**Evidence**:
评测 gqa_68 三轮编译失败（第三轮日志首次给出 stderr：`error: use of undeclared
identifier 'CUDART_INF'`，per_head_bm64/32/16/g2 全链失败）；本地 h5_perf 抽测
clear=False 全量后 case8 main_kernel ×1.798 / case10 ×1.649；examples/gqa/
eval_fix_verify/h5_perf*.log。最终方案（H1-R）：性能敏感主 kernel 恢复
clear=True + 循环前有限哨兵 fill（`T.tile.fill(m_i, m_init_floor)`，覆盖式/
累积式两种 clear 语义下均正确）；回退链末端保留一个 clear=False kernel（g2 兜底）
作为评测机编译失败的兜底（第三轮证据：clear=True 下 56/80 case 编译正常，唯
68 链失败 → 兜底仅需覆盖该类 shape）。

**Proposed change**:
新增 troubleshooting 条目："bisheng 报 use of undeclared identifier 'CUDART_INF'
→ 来自 T.reduce_max/T.reduce_sum 的 clear=True 路径，特定 tilelang-Ascend 构建
缺自包含宏；规避：调用方先 T.tile.fill 有限哨兵 + 按性能/编译环境权衡 clear
取值，并保留 clear=False kernel 作为 dispatch 编译回退链末端"。同时提示跨版本
验证清单应包含"同一 API 在目标 tilelang 构建上的 codegen 差异"。

## Entry e2
- **target_skill**: tilelang-custom-skill/tilelang-api-best-practices
- **target_artifact**: troubleshooting
- **target_section**: "运行时错误.aclnn 561103 算子 binary 缺失"
- **type**: error_code_workaround
- **severity**: high
- **status**: pending

**Observation**:
561103 binary 缺失的**粒度是 op × dtype × 布局变体三维**，此前两轮按 op 粒度
推断替代方案导致剥洋葱（ZerosLike→FillScalar→ViewCopyAiCore 逐层暴露）：
fp32 的 slice 赋值（Mask_full）与 fp16/bf16 crop 的 `.contiguous()` 变体可用，
而 fp16/bf16 的"连续→非连续 slice 赋值"（`out[slab] = t`）走
aclnnInplaceCopy_1_ViewCopyAiCore 缺失。终局方案：**fp16/bf16 路径上所有
NPU 端数据搬运（pad、crop、转置）全部收进自写 tilelang kernel**——transpose
kernel 直接输出 padded 形状（有效区拷贝+pad 行 kernel 内清零）、decode K/V
专用 2-in-1 pad kernel、输出方向 `_transpose_v1` 加 `n_pad` 按真实 S 行写——
torch op 仅保留 torch.empty（无 kernel）、fp32 mask 构造、CPU+H2D。

**Evidence**:
评测 gqa_71/72/73/81/82 三轮演进（ZerosLike→Fill→ViewCopy 各轮 561103）；
examples/gqa/eval_fix_verify/h2_kernel_pad.py：torch dispatch hook guard
11/11 PASS（非对齐 fp16/bf16 bench 路径 0 个 torch device 端拷贝/填充算子）+
numeric 11/11 + 对齐 case bit-exact 7/7；本地 cann-bench 68/68。

**Proposed change**:
更新已有 561103 条目为"三维粒度"结论 + 增加"终局模式"小节：目标环境缺
binary 时不要在 torch op 层找替代（剥洋葱风险），直接把数据搬运收进自写
tilelang kernel（pad-in-transpose / 专用 pad kernel / n_pad 输出裁剪三个
范式，附 gqa.py 实现位置）；并用 dispatch hook guard 做"零危险 op"的结构性
证明。

## Entry e3
- **target_skill**: tilelang-op-develop
- **target_artifact**: skill
- **target_section**: 算子实现 / wrapper 与 kernel 的边界
- **type**: missing_constraint
- **severity**: medium
- **status**: pending

**Observation**:
wrapper 层混合 torch NPU op 与 tilelang kernel launch 的流序在评测机上不可靠
（d2d→launch 竞态，输入逐位相同输出随机 NaN/崩溃）；**结构性消除优于打
synchronize 补丁**——把 pad/crop/转置全部收进 kernel 后，launch 前仅剩 fp32
mask 构造（唯一保留 sync 点），竞态触发面从"每次非对齐调用 3-5 个 d2d"降到
"单点"。用同源 data_generator 做 1620 格矩阵扫描证明不可复现类问题（如
gqa_67）时应以"触发面移除"为修复结论而非仅"本地不复现"。

**Evidence**:
gqa_67 三轮失败本地 1800+ 格（含 ×10 seeds）零复现；H2 后评测路径 d2d 全消
（guard 证明）；gqa_84-100 确定性 SIGSEGV（重试换卡 0/17）的假设修复链为 H2
（非 H1）。examples/gqa/eval_fix_verify/h3_matrix.py / h4_stress.py。

**Proposed change**:
在 op-develop 的 wrapper 设计章节补充约束："面向外部评测/生产的算子，wrapper
与 kernel 之间的 NPU 端 torch op 应最小化到零（数据搬运全 kernel 化），无法
避免时必须在每个 torch-op→launch 边界显式同步；'本地不可复现'的竞态类失败
应以消除触发面为修复标准"。
