### A.1-c 转置形态问题（任务书指定评估项）

任务书问：GEMM1 的 `[KC2=64, block_N=128]` 与 GEMM2 的 `[block_N=128, NC2=64]` 互为转置，能否用**两个独立 `T.alloc_L0B` 声明**绕开 `T.view/T.reshape` 的 `tvm.tir.Buffer` 不可构造问题（`customize.py:94/112`，探针实证 `'Buffer() takes no arguments'`）？

**答：能，已实测（见 A.4）。但这个问题对判决不具决定性**，因为：
- #R8-1 早已给出**更优解**——不做混合 shape，而是把 GEMM2 的 PV 归约**沿 block_N 做 K-split**（`KC2=64`），使 GEMM2 的 B-tile 变成 V 的**行切片** `v_l1[kc2*64:(kc2+1)*64, nc*128:…]`，与 GEMM1 的 `[64,128]` **同向均一**，4 槽共用一个声明。混合 shape 声明因此**无必要**。

**HANG 风险等级（对 A P2 / A P1 chunk 级这两个「容量过门」形态）**

> **风险等级：HIGH（不可由静态审计排除）。**
> 前例：#R10-1 bN=256 全形态 aicore timeout（507014）HANG；**4 轮静态令牌审计全平衡仍挂**（S10-3-2 推论：「静态令牌审计平衡不能排除该类缺陷——判决必须靠运行时变体矩阵」）。A P2 chunk 级同时具备该前例的三个高危特征：(i) **三重顶格零余量**（L0B 64/64、L0A 64/64、L0C 128/128）——S10-3-4 明示「双顶格零余量警示必要不充分」；(ii) 交错使并发 MTE1↔M 令牌流翻倍至 **8/8 零余量**；(iii) 共用池相位纪律解禁 = 引入生产安全谱系从未验证过的**相位内并发 L0B 占用**。
> ⇒ 即便要推进（本判决不建议），**判决必须靠运行时变体矩阵**，且须按 E 系毒化矩阵方法学（S10-3-3）设计，预算 ~7 小时量级。

### B.1-b token 收支处理（对任务书指令的一处**有意偏离**，附理由）

任务书要求「删除 DMA 时必须同时删除其 pipe-pair flag 轮」。**本轮改为：只删 DMA 语句，完整保留每一对 flag 轮（intra-core `SIG_*` 与 cross-core `SEM_*` 全部原位不动）。** 理由：

1. **variant-Y 成对删除规则的真实目的是禁止 X 型非法构造**——iter25 实测证伪的 X 是「**删 wait 保 set**」，其致命点在于 `CrossCoreSetFlag<mode,PIPE>` 阻塞至 PIPE 排空，而配对 wait 的缺失使管道持续深占用 ⇒ X 比生产态慢 +1.7%~+15.8%。本轮**既不删 wait 也不删 set**，任何 flag 的 set/wait 配对**一个都没动**，X 病理**结构性不可能**。
2. **token 收支比 iter24 的「1 dangling」更严格**：生成器内置断言逐字比对四个 flag 家族的存活站点数与生产态**完全相等**——`wait_cross_flag` **27/27**、`set_cross_flag` **32/32**、`set_flag(` **137/137**、`wait_flag(` **137/137**（3/3 探针全部通过）。IR 级复核：`CrossCoreSetFlag` **9→9**、`SetFlag` **62→62**（case9）、`WaitFlag` **53→53**，Δ 全为 **0**。⇒ **零 dangling token，跨核 HANG 结构性不可能**（六个 SEM 对全配对，C↔V pacing 环与生产态逐字同构）。
3. **≤15 硬约束自动满足**：未改动任何 set/wait 配对 ⇒ 每个 flagId 的 outstanding 深度与生产态**逐一相同**，不存在无界累积的 set。
4. **测量隔离更干净**：连 flag 轮一起删会**同时**删掉标量指令并重排 M/FIX/V 握手次序，把「ws 工作被消除」与「协议被简化」混为一谈。保留 flag 轮 ⇒ **唯一被移除的就是那六段 GM 搬运**。
5. 空管道的 `set_flag` 立即排空——这**正是**「该工作已不存在」的物理含义；与 X 不同的是**没有 waiter 被移除**，故不会留下深占用管道。

循环界（`num_fb`/`batch_iters`/`my_count`/`eff_kv_iters`/`total_flat`）纯由标量索引导出、从不读 workspace **数据** ⇒ 载荷消失不可能造出无界循环（沿用 iter25 L3 论证）。

### B.4-c 为什么 W2/W3 反而更慢 —— 根因（实测，非推测）

**根因：CV-over-GM 的 workspace 往返物理上是 L2 往返，不是 DRAM 往返；写侧为读侧提供了 L2 局部性。**

| 证据 | prod | w1（只删 C 侧写） | 判读 |
|---|---|---|---|
| `aic_write_hit_rate(%)`（C 侧 FIX 写 w1/w3） | **98.2629** | 100.0（写已消失，比值失去意义） | **生产态 98.26% 的 workspace 写命中 L2，从不去 DRAM** |

2. **W2（写读都涉及，但只删读的一侧不对称）**：case9 w2 仍读 w2 相关路径而写已消失，冷读代价保留 ⇒ **+0.583% / +0.953% 劣化**。
3. **W3（六段全消）**：冷读代价消失（读也没了），但**DMA 交织所提供的 C↔V 节奏互锁同时消失**，环退化为纯延迟 ping-pong ⇒ 跨核暴露等待 **+78.37 µs**（case9）⇒ **+0.340% / +0.940% 劣化**。

## B.5 工作消除侧与延迟侧可否相加的论证

**结论：不可相加。合计上界 = max(延迟侧, 工作消除侧) = 延迟侧 = 1.1032×（case9）/ 1.1551×（case7）。**

四条论证，前三条为实测：

1. **二者攻击同一个量（实测）**：iter25 已证缺口①（C 侧交错）与缺口③（CV-over-GM 消除）攻击**同一个量**——暴露的跨核等待——故不可相加。本轮 B.4-b 直接测到：消除 656/724 µs 的**工作**后，增量**恰好落在跨核暴露等待上**（case9 `wait_id2` +38.01、`wait_id4` +14.46、`wait_id0` +10.84、`wait_id5` +12.27 = **+78.37 µs**）。**工作消除并没有开辟新的收益通道，它只是把管忙碌换成了同一批 SEM 等待。** 与延迟侧同源 ⇒ 不可相加。
2. **工作消除侧本身为 ≈1.00×，加与不加无差别（实测）**：case9 **1.0060×**、case7 **1.0004×（p=0.669 ns）**。即便错误地采用乘法叠加，case9 也只得 1.1032 × 1.0060 = **1.1099×**，相对 1.1032× 仅多 **0.6%**，远在测量分辨力与达成不确定性之内。**该分量对合计上界的贡献可忽略。**
3. **绝对上界臂为负（实测）**：W3 = 六段全消 = 工作消除的绝对上界，其读数是 **+0.340% / +0.940% 劣化**（p=0.033 / p=0.00092，CI 全正）。一个**负**分量与延迟侧相加没有意义；正确的合并是取 **max**。
4. **物理上界论证（推断，已标注）**：wall 由 pacing 管的「真实工作 + 暴露等待」决定。case9 的真实工作锚 `aiv_vec_time` 468.58 µs / `aic_cube_time` 191.00 µs **在全部三臂逐位不变**；case7 的 `aiv_vec_time` 648.99 µs = AIV wall 的 **77.51%** 亦不变。**任何不触碰真实计算的改造（含完整单域重构中「消除 ws 往返」这一部分）其收益上界就是「暴露等待 → 0」，即 iter25 已钉死的 1.10×/1.16×。** 单域重构若要超越此界，必须削减 `aiv_vec_time`/`aic_cube_time` 本身——那是**算法级**改动（改变 softmax/PV 的计算量），**不属于本轮所界定的「工作消除分量」**，且本轮数据显示 VEC 是 case7 的不可削减 pacing 项。

## F.2 方法学资产更新：iter25 的 6 条「交接类探针」规则是否需要再扩充

**需要。本轮证明「工作消除类探针」与「交接类探针」是两类判读规律不同的探针，必须分章。** iter25 §7.2 的 6 条规则全部围绕「消融**延迟**、保持**工作**不变」设计，其核心判据是**零污染**（所有真实工作管与字节计数器 Δ=0.0000）。本轮消融的**正是真实工作项**，零污染判据**结构性不适用**——若照搬会把每一个合法探针都判为失败。

### F.2-a 新增专章：「工作消除类探针」判读规则（7 条）

| # | 规则 | 本轮实证 |
|---|---|---|
| **WE-1** | **零污染判据不适用，必须替换为「三段式污染账」**：(i) **被消融项**须按预期归零/下降；(ii) **未被消融项**须零变化（黄金标准 = 真实计算管 `aiv_vec_time` / `aic_cube_time` 与 `*_instructions` 逐位相同）；(iii) **发射当量**（`single+2×dual`）须同向小幅下降，以排除「指令变多导致变慢」的混淆 | (i) `aic_fixpipe_time` 336.71→0.00、`L0C_to_GM_datas` −100%；(ii) `aiv_vec_time` case9 **468.58 三臂逐位相同**、`aic_mte1_instructions` Δ=0.0000；(iii) 132.84→121.85 |

### F.2-c 建议入库的三条新硬知识（供 skill / DESIGN 引用）

1. **MHA 的 CV-over-GM workspace 往返物理上是 L2 往返**：C 侧写 L2 命中 **98.26%**、V 侧读 L2 命中 **99.9989%**（miss 计数 0.55）。⇒「省 1032 MB / 46% L2 流量」类宣称的价值 ≈0；且**写侧不可单独移除**（会使读侧冷启，miss ×1770、达成带宽 −11.01%）。
2. **L0B 64KB 在本 kernel 的所有形态下均为 100% 顶格**（`InitBuffer(ascend_l0b, 65536)` 四实现逐字相同）。⇒ 任何「增加并发 B 操作数在途量」的编排（含 GEMM 相位交错、bN 扩大、K-split 加深）在规则内**先验不可行**，应在设计阶段即判否，无需进入实现。
3. **`DESIGN §8.6-10` 共池相位纪律应重新定性**：它不是可调优的编排约束，而是 **L0B 64KB 硬限强制的结构性必要条件**（解禁 ⇒ B 操作数在途量翻倍 ⇒ 128KB）。
