### 1.2 决定性硬件约束（文档 + 双向实测）

CANN AscendC `CrossCoreSetFlag(ISASI)` 约束说明**逐字**：

> **「同一flagId的计数器最多设置15次。」**

生产态 `CROSS_INTERVAL=1` ⇒ 每核每 kernel 每 flagId 约 **461 次 set**（case9 `total_flat`≈461 槽/核）。计数器之所以合法，仅因 set/wait 每槽严格 1:1 交错。

**由此推出的合法性判据（本轮双向实测确认）**：

> 计数器越过 15 后钳位，**当且仅当该 flagId 不再有任何 `CrossCoreWaitFlag` 时无害**；若落后侧仍在 wait 它，则钳位后的计数器最多只能放行 15 次 wait ⇒ **永久阻塞**。

| 实测实例 | 构造 | 结果 |
|---|---|---|
| `xc9l1`/case9、`xc7l1`/case7、`x2s`×2、`x3`×2 | 被删 flagId **无残留 waiter** | **全部 exit 0，无 HANG** |
| `l2c9`/case9、`l2c7`/case7 | 一侧 wait 全删 ⇒ 该侧自由跑 ⇒ **另一侧仍在 wait 的 flagId** 无界累积 | **双双 HANG**（240 s SIGKILL，exit 137） |

### 1.3 token 收支处理方式 —— **成对删除（variant Y）为唯一合法方案**

| 方案 | 计数器行为 | 合法性 | 实测 |
|---|---|---|---|
| **成对删除 wait+set（Y）** | 被删 flagId 计数器**冻结**在 init 值（SEM1/3/5 各 1，SEM0/2/4 各 0），永不增减 | ✅ **零饱和风险**；L3 下全域无任何 `CrossCoreWaitFlag` 残留 ⇒ **跨核 HANG 结构性不可能** | 4 级 × 2 case 全部 exit 0 |
| 保留 set 只删 wait（X） | 被删 flagId 计数器单调增长至 ~461，越过 15 后钳位 | ⚠️ 无 HANG（无 waiter），**但引入生产态没有的新阻塞**（见 §1.5） | 全部 exit 0，**wall 反升 +1.7%~+15.8%** |
| 一侧 wait 全删（字面 L2） | **对侧**仍被 wait 的 flagId 无界累积 | ❌ **非法** | **HANG ×2** |

**HANG 风险评估（逐级，构造性证明 + 实测双保险）**

| 级别 | 残留 flagId 最大 outstanding 深度 | 论证 | 实测 |
|---|---|---|---|
| L1（case9：删 SEM0/SEM4 对；case7：删 SEM2 对） | **≤ 8**（= `NUM_STAGES`） | 残留的每轮握手把 C/V 错位钳在 ≤1 轮内 ⇒ 每槽 SEM 最多积压一个批（8 槽）；每轮 SEM ≤2 | 无 HANG |
| L2s（删全部**每槽** SEM0/2/4 对，保留全部**每轮** SEM1/3/5 对） | **≤ 2** | 保留的每轮环仍双向节流 ⇒ 错位 ≤1 轮 ⇒ 每轮 SEM outstanding ≤2 | 无 HANG |
| L3（6 个 SEM 对在两个 C 分支全删） | **= 1**（仅 init 预置） | 全域无 `CrossCoreWaitFlag`；且所有循环界（`num_fb`/`batch_iters`/`my_count`/`eff_kv_iters`/`total_flat`）**纯由标量索引导出，从不读 workspace 数据** ⇒ 丢失握手不可能造出无界循环 | 无 HANG |
| 字面 L2 | **无界（≫15）** | 一侧零 wait ⇒ 自由跑 | **HANG** |

> 15 上限的最紧余量出现在 L1（8/15，余 7）——**与生产态同深度**（生产态 SEM2 每轮亦积压至 8，因 C.GEMM2(fb) 头 wait SEM5 = V.phase2(fb−1) 结束，而 V.phase2 在 V.phase1 之后）。即 L1 未引入任何生产态不存在的计数器深度。

### 1.5 变体 X vs 变体 Y —— **任务书假设被实测证伪，这是本轮第二大发现**

任务书设想「变体 X（只删 wait）= 测纯延迟暴露」。**实测结论：X 不是纯延迟探针，它是「延迟移除 + 新增排空阻塞」，且新增项压倒性地主导。**

| paired 对比（X − Y，µs） | 均值差 | SEM | t(df=2) | p |
|---|---|---|---|---|
| case9 X@L1 − Y@L1 | **+102.830** | 0.518 | +198.55 | <1e-4 |
| case9 X@L3 − Y@L3 | **+218.800** | 1.732 | +126.31 | 1e-4 |
| case7 X@L1 − Y@L1 | **+130.533** | 1.070 | +122.04 | 1e-4 |
| case7 X@L3 − Y@L3 | **+162.600** | 1.971 | +82.48 | 1e-4 |

**机制（计数器直接指认，非推测）**：`CrossCoreSetFlag<mode,PIPE>` 是**阻塞至 PIPE 排空**的标量指令。生产态里配对的 `CrossCoreWaitFlag` 使管道保持浅占用，故每次 set 的排空近乎免费；**删掉 wait 而保留 set，每一次 set 就变成生产态从未有过的全管排空阻塞点**。证据：

### 4.2 缺口① 天花板（延迟侧）

**缺口①（C 侧 GEMM1/GEMM2 交错，让 Cube 在等 P 时有活干）天花板 = case9 −9.36% / case7 −13.43%。**

依据：缺口① 不减少 ws 字节、不改变任何真实工作，只把 C 的**暴露等待**换成 C 自己的有用工作。本轮探针在**所有真实工作管与全部字节/指令计数器逐位不变**（§2.2b）的前提下把 C 的暴露跨核等待压到 ≈0（case9 `wait_id2` 211.86 → **0.59**，−99.72%；case7 `wait_id2` 534.10 → **列消失**）。**任何合法的 C 侧交错至多达到「C 暴露等待 ≈0 且 C 真实工作不变」这一状态，即本轮 L1/L3 的 C 侧状态。** 故上界成立。

**⚠️ 上界 ≠ 期望值，且有两条实测警示：**

1. **环的对称性证明缺口① 的因果假设不完整**：case9 L1 **只**消融了 V 侧等待，C 侧暴露等待却**免费坍塌**（`wait_id2` −99.72%、`wait_id1` −99.43%、`wait_id5` → 列消失），双侧 `aic_time`/`aiv_time` 同步各降 ~76–78 µs。⇒ **在闭环里，一侧的等待就是另一侧的延迟，二者互相生成、不可独立归因或独立消融。** 「C 在等 P 时没活干」不是独立病因，而是环的症状。
2. **交错后的新限制在 MTE1 队列/L0B，而那里是零余量**：消融后 case9 AIC 有 **89.4%** 时间在 `scalar_mte1_stall`。GEMM1 的 k-chunk 与 GEMM2 的 n-chunk **共用同一 `l0b_pool` 与同一 `SIG_L0KC` 事件流**（§4.5-d-2）；把 GEMM1(fb+1) 与 GEMM2(fb) 交错会**使该共享池的并发 MTE1↔M 令牌流翻倍**，正撞任务书所列的 **L0B 64KB 零余量**与 **MTE1↔M event id 8/8 零余量**（#R8-1 实测已用 7/8）。

### 4.3 缺口③ 天花板（延迟侧）+ 字节侧非绑定复核

**缺口③（架构级消除 CV-over-GM 往返）延迟侧天花板 = 同一组数：case9 −9.36% / case7 −13.43%。**

理由：缺口③ 消除的正是本探针消除的东西——GM 往返的**延迟暴露**。缺口① 与缺口③ 攻击**同一个量**，故**二者不可相加**，其合计上界就是这一个数。

**字节侧：确定非绑定 —— 双向钳形闭合（对上轮推断的复核结论 = 成立并加强）**

| 实验 | 对字节/L2 的扰动 | wall 响应 |

| **iter24**（Q 消融） | `GM_to_L1` **−1622.4 KB**、`aic_r0_read_cache_miss_allocate` **−34.76%/−34.55%**、`aic_read_hit_rate` **+2.64pp/+2.34pp** | case9 **+0.288%**（p=0.177 ns）/ case7 **+0.871% 劣化**（p=0.025）⇒ **大幅改字节，wall 不动** |

## 5. 决策建议

### 5.1 缺口①（解禁 DESIGN §8.6-10，C 侧 GEMM1/GEMM2 交错）：**CONDITIONAL GO**

**支持 GO 的定量依据**
- EV 上界 **−9.43%（case9 L1）/ −12.93%（case7 L1）**，为 3% 采纳门的 **3.1× / 4.3×**；p ≤ 2.1e-04，SEM ≤1.19 µs，**统计上无可争议**。
- **M1 越线只需 −2.500% wall = 上界的 26.5% 捕获率**。这是一个**宽松**的达成条件——不需要接近完美交错。
- 上轮的替代路径已关闭（GATE 2 `q_l1` 双缓冲 NO-GO，上界 ≤+0.33%；路径 2 bN=256 结构性不可行并永久禁令），**缺口① 是规则内唯一剩余的非零上界杠杆**。

**使 GO 只能是「有条件」的两条实测依据**
1. **可行性前置门未过（阻塞项）**：消融后 case9 AIC 有 **89.4%** 时间处于 `scalar_mte1_stall`，而 `aic_mte1_time` busy 仅 43.7% ⇒ 新限制是 **MTE1 队列深度**。交错 GEMM1(fb+1)/GEMM2(fb) 会使**共用 `l0b_pool` 与共用 `SIG_L0KC` 事件流**（§4.5-d-2）的并发 MTE1↔M 令牌流翻倍，正撞 **L0B 64KB 零余量** + **MTE1↔M event id 8/8 零余量**（#R8-1 已用 7/8）。**在 event-id / L0B 预算审计通过之前，交错方案在本 kernel 内可能根本不可表达。**
2. **因果假设不完整**：§4.2 警示 1 证明 C 的暴露等待是环的**症状**而非独立病因；给 C 加 busywork 不等于打断环。上界成立，但**捕获率无任何实测下界**（本轮无法给出，见 §6.3）。

**具体建议**：**不做 §8.6-10 的全面解禁**，改为**一次范围受控、探针门控的试验**：
- 前置门 A（**必须先过**）：event-id / L0B 容量审计——列出交错形态所需的 MTE1↔M 令牌流与 L0B 工作集，若 >8 id 或 >64KB ⇒ **直接 NO-GO，无需写 kernel**。
- 前置门 B：以本轮 `l1c9`/`l3` 的 max-block 读数为标尺，任何候选实现的 `aic_scalar_mte1_stall` 若高于 y_L1 的 685.05 µs，说明交错把延迟换成了更坏的队列阻塞，应即弃。
- 爆炸半径按任务书全额计入：全 20 case 复测 + 失去 IR 逐字节守卫 + timeout HANG 前例（本轮再添两例：`l2c9`/`l2c7`）。
- **判据**：case9 需 ≥3%（= 上界 31.8% 捕获）才采纳；若落在 2.5%~3% 之间，属「越 M1 线但未过采纳门」，须由 Orchestrator/用户裁决是否放宽门。

### 5.2 缺口③（架构级 CV-over-GM 消除，需 A5 或框架级 L2 直连通道）：**延迟侧 NO-GO / 工作消除侧 UNMEASURED**

**NO-GO 的定量依据（延迟侧）**
- 延迟上界 **≤9.36%（case9）/ ≤13.43%（case7）**，即 **1.10× / 1.15×**。
- 其**字节侧价值 ≈ 0**（§4.3 双向钳形 + 71–81% 带宽余量）⇒ 宣称的「省 1032 MB / 46% L2 流量」**不是收益**。
- **投入产出不成比例**：为换取**至多**与「规则内缺口①」同一个上界，需付出**框架级/A5 级跨项目投资**。**用框架级资本去获得规则内改造本就可能获得的东西，不成立。**

**不可越界宣称的部分（如实标注）**

本轮产生 5 条上轮方法学未覆盖的、可复用的硬规则，建议写入 `tilelang-perf-optimization`：

1. **【新】跨核 SEM 消融必须成对删除 wait+set（variant Y）；只删 wait（variant X）在 Ascend 上是无效探针。**
   实测代价：X 比生产态**更慢** +1.7%~+15.8%，X−Y 达 +102.8~+218.8 µs（p≤1e-4）。根因：`CrossCoreSetFlag<mode,PIPE>` 是**阻塞至 PIPE 排空**的标量指令（`codegen_ascend.cc:2871`），生产态由配对的 wait 保持管道浅占用使其近乎免费；删 wait 保 set ⇒ 每次 set 变成新的全管排空阻塞点。**识别特征：发射当量（`single+2×dual`）不变而 `scalar_time`/`*_stall`/`wait_ib` 齐涨。**

2. **【新】硬件计数器上限：`CrossCoreSetFlag` 同一 flagId **最多 15 次未消费 set**（CANN 文档约束说明）。**
   推论出的合法性判据（本轮双向实测确认）：**钳位在「该 flagId 无残留 waiter」时无害，在「落后侧仍 wait 它」时致命（永久阻塞）。**
   ⇒ **消融级次不是单调安全的**：L1（删一对）与 L3（删全部）合法，**字面 L2（删一侧全部 wait）非法并 HANG**。设计逐级阶梯时必须逐级做 outstanding 深度证明（每槽 SEM ≤ `NUM_STAGES`，每轮 SEM ≤ 2），而非假设「删得越多越接近上界故越安全」。

3. **【新】`wait_idN` 列的存亡本身即激活信号。** msprof 对 20 block 全零的 `wait_idN` **直接删除该列**；且生产态只出现跨核 SEM 的方向分割（AIC id1/2/5、AIV id0/3/4），核内 `SetFlag/WaitFlag` 的 SIG id 一个都不出现 ⇒ **`wait_idN` ↔ `CrossCoreWaitFlag(N)` 1:1**，核内等待归入 `*_mte1_stall`/`*_cube_stall`/`*_vector_stall`/`wait_ib` 桶。**用列存亡判激活，比读数值更抗假阴性。**

4. **【新】必须用「发射当量」排除「指令变少」混淆。** 删同步指令会同时减少标量指令数；若只报 `scalar_time` 下降，无法区分「阻塞变少」与「指令变少」。判据 = `scalar_single_time + 2×scalar_dual_time` 恒定（本轮 Δ≤1.53 µs = wall 的 0.17%）而 `scalar_time` 崩塌（−684 µs）⇒ 纯阻塞移除。**建议列为消融类探针的强制第 4 项检查**（与上轮的「真实工作管零变化」「字节/指令计数器零变化」「rel_max 发散」并列）。

5. **【强化】吸收律定量化：`wait_idN` 之和把可回收 wall 高估 6.8×~9.4×**（case9 9.35×、case7 6.81×；转化率越低倍数越高）。
   本轮转化率实测 10.69%（case9）/14.69%（case7）；上轮为「移除真实工作 → wall 反升」。**两者合并的规律：任何以「累加 stall/wait 计数器」得出的 EV 都必须除以 7~10 才是 wall 量级，且必须报告迁移目标计数器（本轮为 `wait_id3` +308.30 µs、`wait_id1` +203.22 µs、`mte1_stall` +151.19/+216.68 µs、`vector_stall` +152.67/+59.11 µs）以证明是迁移而非消失。**

6. **【新】原位 `if False: <原语句>` 改写模式**（替代上轮的条件改写）：适用于需要**删除**语句而非改条件的消融。优点：行数恒定 ⇒ diff 行数可精确断言；不需要 `pass`（TVMScript 对空块/`pass` 的支持未验证）；`if <Python 静态 bool>:` 机制在 mha.py 中已被 `if is_causal`/`if not io3_is_alias`/`if need_mask` 大量依赖，故解析安全性有既有先例。本轮 10 个探针、1–18 行 delta，**全部一次编译通过，零解析错误**。
